# Build — from an issue to a PR standing at the gate

**Nature: Transmuter** for machinery, **Conjurer** for canon/governance, **Enhancer** for product
code; the mode is named at § 2, and said aloud when it switches mid-run.

> **Give me an issue; I execute the canonical Hatsu protocol (`ten` → `classify` → `direct` → `ren` →
> `aka` → `mukai` → `en` → `rikugan` → `third-hand`) and deliver a PR that is `CON-32`-Ready at its human
> gate — or a G5 stop saying exactly why it could not get there.**

**Hatsu holds no CI plane to route work to** (no CI agent routing, stage labels, wave coordinators or wake
ladders). Instead, building an issue is a direct local-plane execution of the canonical Hatsu feature pipeline: warm up
([`/ten`](../ten/SKILL.md)), classify the issue when its two axes are not yet labelled
([`/classify`](../classify/SKILL.md)), direct it — the recommended model, surface and effort against this
session's ([`/direct`](../direct/SKILL.md)) — author and locally verify ([`/ren`](../ren/SKILL.md)),
publish branch ([`/aka`](../aka/SKILL.md)), run pre-PR review, tests, coverage, and open PR
([`/mukai`](../mukai/SKILL.md)), observe and drive PR to readiness ([`/en`](../en/SKILL.md)), render
the delivered state ([`/rikugan`](../rikugan/SKILL.md)), and harvest friction
([`/third-hand`](../third-hand/SKILL.md)).

**The phases this composite calls skip their own `## 0.`**
([`docs/STANDALONE-ENTRY.md`](../../../docs/STANDALONE-ENTRY.md) § 4); the plugin root is
[`docs/PROCESS.md`](../../../docs/PROCESS.md) § *Authority every phase shares*.

## 1. Invocation

**P1 — this run opens with `/ten build`** ([`ten`](../ten/SKILL.md) § 6 catches up this phase's
missing prerequisites under its own name; the phases this run calls skip theirs).

```
/build <product|repo_code>#<issue_number>
nen parse build --grammar "<code>#<n>" --line "<the raw invocation>"
nen repo resolve <CODE> --repo <the target repo's own checkout>
```

Case-insensitive; **a code is resolved, never guessed**. A missing argument or configuration item is
asked for and set up inline (`missing-argument`, `missing-configuration`;
[`docs/WORKFLOW.md`](../../../docs/WORKFLOW.md) § 4 *Ask, set up, continue*): `nen parse` exit `2` or an
unresolved code is the trigger, registered codes the options, absent entry set up in `nen/repos.json`.

**If `#<N>` is already a PR**, do not re-author: hand straight to
[`/en on <CODE>#<N>`](../en/SKILL.md) to drive it to readiness, and say so. Inspect `#<N>` via
`gh api repos/<owner>/<repo>/issues/<N> --jq '.pull_request'`; if populated, it is a PR.

**Say the run started**: it holds a bounded `CON-25` delegation (§ 5), and an unannounced delegation
is one nobody can end.

## 2. Inspect the issue and confirm the mode

Read the target issue before touching code:

```bash
gh issue view <N> --repo <owner/name> --json title,body,state,labels,closedByPullRequestsReferences
```

- **If closed**: the run ends immediately, reporting what closed it and which PR delivered it (from
  `closedByPullRequestsReferences`).
- **If an epic awaiting approval**: stop at **G1** (row `mode-label`) — the mode label is the
  maintainer's decision (`CON-4`), never an agent's.
- **Read requirements**: extract issue title, body, acceptance criteria, and technical constraints.

**Confirm Kurapika's work-mode** from the domain and nature of the issue:

| Issue domain / content | Mode |
|---|---|
| Product code implementation, UX, customer-facing behaviour | **Enhancer** |
| Canon prose, governance, constitution (`CON-{n}`), specifications, schemas | **Conjurer** |
| Machinery, tooling, plugin, workflows, scripts, automation | **Transmuter** |

**With ambiguity, propose one and ask** — a wrong mode makes a plausible, wrongly shaped PR: a
**`DECIDE`** per [`jutaisho`](../jutaisho/SKILL.md) § 4, row `mode-unknown`, once per run. A G1
stop is never a mode question: for an unapproved epic the ask is the mode *label*, and **only the
maintainer applies it** (`CON-4`).

### 2b. Classify, when the issue is not — then direct

```bash
nen classify status --taxonomy "$hatsu_root/contracts/classify.taxonomy.json" --repo <checkout> --target <owner/name> --issue <N> --json
```

The host nen predates the pin (`unknown command`; row `missing-tool`): one line — `classify/direct unavailable at
nen <version>; build continues unrouted, install the pin (ten § 2)` — then § 3. Otherwise a `missing` axis runs
[`/classify`](../classify/SKILL.md) § 3 here, its rows shown then applied under this run's go (classify
§ 5); an undecidable axis stays empty, said (row `classify-undecidable`), never re-classified downstream. Then,
every run, `/direct <CODE>#<N>` with the session's `--surface`, `--model` and `--effort` (`unread` where
unexposed): [`direct`](../direct/SKILL.md) § 5 reports the verdict beside the session's and § 6 owns the
mismatch — row `direct-mismatch`, asked once, **never a block**; **B** ends the run naming what to open. The
verdict is recorded in `.nen/direct/<CODE>-IS-%23<N>.json` (the id percent-encoded by the verb), the answer by
`nen direct answer`.

## 3. Worktree isolation by default

All authoring, feature work, and verification for the issue **must run in an isolated git worktree**
([`docs/WORKFLOW.md`](../../../docs/WORKFLOW.md) § *Where worktrees live*):

```
<core>/.nen/worktrees/<surface>/<name>
```

Git-ignored inside core, never a sibling; branch `{model}/{persona}/{descriptor}` (`nen/workflow.json`); core
stays clean and parked on the trunk unless the maintainer's own prose says to work on core.

## 4. The canonical feature building protocol

Build drives the issue through the canonical Hatsu pipeline, § 2b's intake first:
`ten` → `classify` (when unclassified) → `direct` → `ren` → `aka` → `mukai` → `en` → `rikugan` → `third-hand`.

**Each phase is another skill's, named and linked; its procedure, stops and residue live there.**

| Phase | Skill | What build takes from it |
|---|---|---|
| **1 · author** | [`/ren`](../ren/SKILL.md), turn after turn: `breath` (first turn: fast-forward, cut, prove the base) → `rasengan` → `kokusen` (checkpoint, triage, the commit with `Hatsu-Agent: Kurapika`) → `amaterasu` → `spiritual-message` → `jutaisho` | every acceptance criterion met and committed locally; never a push |
| **2 · publish** | [`/aka`](../aka/SKILL.md): `gyo` → squash the unpushed → `ao` → `gyo` again if the tree moved → push | the branch on origin; no PR |
| **3 · PR** | [`/mukai`](../mukai/SKILL.md): `murasaki` → `hanten` → `kokusen` → `kotoamatsukami` → `byakugan` → evidence → `shibari` (the nine-part body, `nen pr body-check`, the evidence and Development guards, each `Closes #<N>` under the Associated-issues table) → landing report → `en` offered, or started under `mukai.autoEn` | one open PR, the four pre-PR G5 stops honoured |
| **4 · readiness** | [`/en on <CODE>#<PR>`](../en/SKILL.md): the capped acting cycle, `sharingan` and `murasaki`, `nen pr ready` quoted verbatim, the bell at Ready | the PR at its merge prompt (**G2**, **G4** in a canon repository); En never merges |

### Phase 5: `rikugan` — The delivered state, seen once

The final Rikugan page — one register row per issue and PR this run touched, the `nen pr ready` verdict quoted
verbatim, spend, legend — is **`en` § 8's own render at its terminus** ([`rikugan`](../rikugan/SKILL.md)
`final`), reached through En and **never rendered a second time by build**; it is named here as the phase it
is. Read-only; it advances nothing.

### Phase 6: `third-hand` — Post-En session harvest

Run [`/third-hand`](../third-hand/SKILL.md) to harvest process friction:

- Runs after En completes and rikugan has rendered.
- Raise Netero (`third-hand · netero · <model alias>`) to read sitting transcript.
- Propose 0–3 folded issues through surface picker.
- File only what maintainer chooses with [`file`](../file/SKILL.md), then close session.

## 5. Authority — what this run may and may not do

`CON-25`'s fourth carve-out: holds run-scoped delegation bounded to the pipeline phases.

| | |
|---|---|
| **May execute** | canonical pipeline (`ten` → `classify` → `direct` → `ren` → `aka` → `mukai` → `en` → `rikugan` → `third-hand`) for target issue; classify's labels under this run's go, direct's verdict recorded |
| **May author & commit** | in isolated worktree with Conventional Commits and `Hatsu-Agent: Kurapika` |
| **May publish & open PR** | via `aka` and `mukai` using compliant `shibari` template linking the issue |
| **May drive to readiness** | via `en` until `nen pr ready` exits 0 |
| **No CI plane** | holds no CI plane: no CI builder wakes, stage routing, or wave coordinator algorithms |
| **Never** | merges PR (G2/G4 stays maintainer's), applies G1 mode label, votes on reviews, or works on core |

**The delegation expires when the run ends. Say when it ends.**

## 6. When it will not move (G5)

A stall is reported plainly — the blocker, and whether it needs the maintainer: a gap unresolvable locally
is a **G5** naming it, rendered as `nen stop`'s banner with lettered options and the star per
[`jutaisho`](../jutaisho/SKILL.md) § 4; filing is a legitimate outcome ([`file`](../file/SKILL.md), linked,
the build held on it).

## 7. Reporting

Every report follows [`docs/PROCESS.md`](../../../docs/PROCESS.md) § *Reporting a phase*:
[`spiritual-message`](../spiritual-message/SKILL.md) for `ren` turns and the `mukai` landing,
[`rikugan`](../rikugan/SKILL.md) for the final state at `en`'s terminus; a gate quotes `nen pr ready`'s
verdict verbatim.

| Gate | When | The ask |
|---|---|---|
| **G1** | epic awaits mode label (row `mode-label`) | `DECIDE`, with trade-off |
| **G2/G4** | delivery PR is `CON-32`-Ready (rows `merge`, `canon-merge`) | `MERGE`, verdict saying everything |
| **G5** | stuck build or capability gap | `DECIDE`/`DO` with proposed issue; tool per `missing-tool` |

Run **ends** when delivery PR stands Ready at human gate, issue is closed, or at G5 stop: say which,
and that delegation lapsed.

## 9. Hard limits

- **Never merges a PR** (`CON-5`/`CON-7`, rows `merge`/`canon-merge`); G2/G4 remain maintainer's gate.
- **Never applies a G1 mode label** on an epic.
- **Never votes, self-reviews, or casts `request_changes`** (`CON-26`).
- **Never routes work to CI builders** or invokes retired Bankai CI capabilities.
- **Never authors, branches, or commits on core checkout** by default (Rule 6).
- **Never uses raw `gh pr create`** or skips Mukai's composite steps.
- **Never blocks on `direct`'s verdict or on an absent verb**, never asks the mismatch twice, and never
  starts a subsession **to act on direct's recommendation** — it is for the maintainer's own session; every
  subagent keeps its `models.roles` tier and never the frontier tier (WORKFLOW § `models`).
- **Never commits without Conventional Commits body and `Hatsu-Agent: Kurapika` trailer**.
- **Never leaves delegation open** — say when it ends.
