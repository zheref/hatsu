# Build — from an issue to a PR standing at the gate

**Nature: Transmuter** for machinery, **Conjurer** for canon/governance, **Enhancer** for product
code; the mode is named at § 2, and said aloud when it switches mid-run.

> **Give me an issue; I execute the canonical Hatsu protocol (`ten` → `classify` → `direct` → `ren` →
> `aka` → `mukai` → `en` → `rikugan` → `third-hand`) and deliver a PR that is `CON-32`-Ready at its human
> gate — or a G5 stop saying exactly why it could not get there.**

**Hatsu holds no CI plane to route work to** (no CI agent routing, stage labels, wave coordinators or wake
ladders). Instead, building an issue is a direct local-plane execution of the canonical Hatsu feature pipeline: warm up
([`/ten`](../ten/SKILL.md)), classify the issue when its two axes are not yet labelled
([`/classify`](../classify/SKILL.md)), direct it — the recommended model, surface and effort against this
session's ([`/direct`](../direct/SKILL.md)) — author and locally verify ([`/ren`](../ren/SKILL.md)),
publish branch ([`/aka`](../aka/SKILL.md)), run pre-PR review, tests, coverage, and open PR
([`/mukai`](../mukai/SKILL.md)), observe and drive PR to readiness ([`/en`](../en/SKILL.md)), render
the delivered state ([`/rikugan`](../rikugan/SKILL.md)), and harvest friction
([`/third-hand`](../third-hand/SKILL.md)).

**The phases this composite calls skip their own `## 0.`**
([`docs/STANDALONE-ENTRY.md`](../../../../docs/STANDALONE-ENTRY.md) § 4); the plugin root is
[`docs/PROCESS.md`](../../../../docs/PROCESS.md) § *Authority every phase shares*.

## 1. Invocation

**P1 — this run opens with `/ten build`, never skipped** ([`ten`](../ten/SKILL.md) § 6 catches up this
phase's missing prerequisites under its own name; the phases this run calls skip theirs). **Self-hosting** (nen's or
Hatsu's own checkout): a host `nen` behind the pin is ten § 1's `BEHIND`/`WRONG` row and § 2's install,
never read `ok`; a checkout **ahead of every release** keeps the pinned `nen` on `PATH` and exercises the
code under build from the checkout itself (nen: `bun src/index.ts`), said in every brief (hatsu#229).

```
/build <product|repo_code>#<issue_number>
nen parse build --grammar "<code>#<n>" --line "<the raw invocation>"
nen repo resolve <CODE> --repo <the target repo's own checkout>
```

Case-insensitive; **a code is resolved, never guessed**. A missing argument or configuration item is
asked for and set up inline (`missing-argument`, `missing-configuration`;
[`docs/WORKFLOW.md`](../../../../docs/WORKFLOW.md) § 4): `nen parse` exit `2` or an unresolved code is the
trigger, the registered codes the options.

**If `#<N>` is already a PR** (`gh api repos/<owner>/<repo>/issues/<N> --jq '.pull_request'` populated), do
not re-author: hand straight to [`/en on <CODE>#<N>`](../en/SKILL.md), and say so.

**Say the run started**: it holds a bounded `CON-25` delegation (§ 5), and an unannounced delegation
is one nobody can end.

## 2. Inspect the issue and confirm the mode

Read the target issue before touching code:

```bash
gh issue view <N> --repo <owner/name> --json title,body,state,labels,closedByPullRequestsReferences
```

- **If closed**: the run ends immediately, reporting what closed it and which PR delivered it (from
  `closedByPullRequestsReferences`).
- **If an epic awaiting approval**: stop at **G1** (row `mode-label`) — the mode label is the
  maintainer's decision (`CON-4`), never an agent's.
- **Read requirements**: extract issue title, body, acceptance criteria, and technical constraints.

**Confirm Kurapika's work-mode** from the domain and nature of the issue:

| Issue domain / content | Mode |
|---|---|
| Product code implementation, UX, customer-facing behaviour | **Enhancer** |
| Canon prose, governance, constitution (`CON-{n}`), specifications, schemas | **Conjurer** |
| Machinery, tooling, plugin, workflows, scripts, automation | **Transmuter** |

**With ambiguity, propose one and ask** (a `DECIDE`, [`jutaisho`](../jutaisho/SKILL.md) § 4, row
`mode-unknown`, once per run). A G1 stop is never a mode question: an epic's mode *label* is the
maintainer's alone (`CON-4`).

### 2b. Classify, when the issue is not — then direct

```bash
nen classify status --taxonomy "$hatsu_root/contracts/classify.taxonomy.json" --repo <checkout> --target <owner/name> --issue <N> --json
```

A host nen predating the pin (`unknown command`; row `missing-tool`) is one line — `classify/direct
unavailable at nen <version>; build continues unrouted` — then § 3. Otherwise a `missing` axis runs
[`/classify`](../classify/SKILL.md) § 3 here, applied under this run's go; an undecidable axis stays
empty (row `classify-undecidable`). Then, every run, `/direct <CODE>#<N>` with the session's
`--surface`, `--model` and `--effort`: [`direct`](../direct/SKILL.md) § 5 reports the picks, § 6 owns the
compare (within the set one line; outside it row `direct-mismatch`, asked once, **never a block**, **B**
ending the run). The verdict is recorded under `.nen/direct/`, the answer by `nen direct answer`; direct § 7
publishes under `direct.publish` only.

## 3. Worktree isolation by default

All authoring, feature work, and verification for the issue **must run in an isolated git worktree**
([`docs/WORKFLOW.md`](../../../../docs/WORKFLOW.md) § *Where worktrees live*):

```
<core>/.nen/worktrees/<surface>/<name>
```

Git-ignored inside core, never a sibling; branch `{model}/{persona}/{descriptor}` (`nen/workflow.json`); core
stays clean and parked on the trunk unless the maintainer's own prose says to work on core. **One checkout
per concurrent effort** (hatsu#229): a second issue is never started in an occupied worktree — it gets
its own `<name>` — and a tree a reviewer is reading is never switched under them: hanten § 4's detached
checkout exists for that, and where it could not be made (an isolated session), the run waits for the
review to return before the branch moves.

## 4. The canonical feature building protocol

Build drives the issue through the canonical Hatsu pipeline, § 2b's intake first:
`ten` → `classify` (when unclassified) → `direct` → `ren` → `aka` → `mukai` → `en` → `rikugan` → `third-hand`.

**Each phase is another skill's, named and linked; its procedure, stops and residue live there.** What
build itself writes: `nen phase begin|end --effort <branch> --phase <1·author|2·publish|3·PR|4·readiness>`
around each phase, and `nen usage record` at every § 7 report ([`WORKFLOW.md`](../../../../docs/WORKFLOW.md)
§ *The effort's ledgers*) — **owed on every target, a stage taxonomy or not**. On a target whose
`nen/labels.json` declares no delivery stages (nen's own, Hatsu's own) **no stage label is applied and none
is manufactured** (WORKFLOW § *A target repository with no delivery-stage taxonomy*): the release into building
is the typed invocation; the chain position is read off the issue, never computed; ledgers, PR and
Development links are unchanged (hatsu#229).

| Phase | Skill | What build takes from it |
|---|---|---|
| **1 · author** | [`/ren`](../ren/SKILL.md), turn after turn: `breath` → `rasengan` → `kokusen` (the commit with `Hatsu-Agent: Kurapika`) → `amaterasu` → `spiritual-message` → `jutaisho` | every acceptance criterion met and committed locally; never a push |
| **2 · publish** | [`/aka`](../aka/SKILL.md): `gyo` → squash the unpushed → `ao` → `gyo` again if the tree moved → push | the branch on origin; no PR |
| **3 · PR** | [`/mukai`](../mukai/SKILL.md): `murasaki` → `hanten` → `kokusen` → `kotoamatsukami` → `byakugan` → evidence → `shibari` (the body, `nen pr body-check`, the evidence and Development guards) → landing report → `en` offered, or started under `mukai.autoEn` | one open PR, the four pre-PR G5 stops honoured |
| **4 · readiness** | [`/en on <CODE>#<PR>`](../en/SKILL.md): the capped acting cycle, `sharingan` and `murasaki`, `nen pr ready` quoted verbatim, the bell at Ready | the PR at its merge prompt (**G2**, **G4** in a canon repository); En never merges |

### Phase 5: `rikugan` — The delivered state, seen once

The final Rikugan ([`rikugan`](../rikugan/SKILL.md) `final`) is **`en` § 8's own render at its terminus**,
never rendered a second time by build; read-only, it advances nothing.

### Phase 6: `third-hand` — Post-En session harvest

After En completes and rikugan has rendered, [`/third-hand`](../third-hand/SKILL.md) raises Netero
(`third-hand · netero · <model alias>`) over the sitting, proposes 0–3 folded issues through the picker,
files only what the maintainer picks ([`file`](../file/SKILL.md)), and closes the session.

## 5. Authority — what this run may and may not do

`CON-25`'s fourth carve-out, bounded to the pipeline phases: the canonical pipeline for the target issue,
classify's labels under this run's go and direct's verdict recorded; authoring and commits in the isolated
worktree (Conventional Commits, `Hatsu-Agent: Kurapika`); the push through `aka` and the PR through `mukai`'s
`shibari`, linking the issue; `en` until `nen pr ready` exits `0`. No CI plane: no builder wakes, stage
routing or wave coordination. Never a merge (G2/G4 stay the maintainer's), a G1 mode label, a review vote,
or work on core.

**The delegation expires when the run ends. Say when it ends.**

## 6. When it will not move (G5)

A stall is reported plainly — the blocker, and whether it needs the maintainer: a gap unresolvable locally
is a **G5** naming it, in [`jutaisho`](../jutaisho/SKILL.md) § 4's shape; filing is a legitimate outcome
([`file`](../file/SKILL.md), linked, the build held on it).

## 7. Reporting

Every report follows [`docs/PROCESS.md`](../../../../docs/PROCESS.md) § *Reporting a phase*:
[`spiritual-message`](../spiritual-message/SKILL.md) for `ren` turns and the `mukai` landing,
[`rikugan`](../rikugan/SKILL.md) for the final state at `en`'s terminus; a gate quotes `nen pr ready`'s
verdict verbatim.

**G1**: an epic awaiting its mode label (row `mode-label`), a `DECIDE` with the trade-off. **G2/G4**: the
delivery PR `CON-32`-Ready (rows `merge`, `canon-merge`), a `MERGE` whose verdict says everything. **G5**: a
stuck build or capability gap, `DECIDE`/`DO` with the proposed issue (a tool per `missing-tool`). The run
**ends** when the PR stands Ready at its gate, the issue is closed, or at a G5 stop: say which, and that the
delegation lapsed.

## 9. Hard limits

- **Never merges a PR** (`CON-5`/`CON-7`, rows `merge`/`canon-merge`), **applies a G1 mode label**, or
  **votes, self-reviews or casts `request_changes`** (`CON-26`).
- **Never routes work to CI builders**, authors on the core checkout by default, uses raw `gh pr create`, or
  skips Mukai's composite steps.
- **Never blocks on `direct`'s verdict or on an absent verb**, never asks the mismatch twice, and never
  starts a subsession **to act on direct's recommendation** — it is for the maintainer's own session; every
  subagent keeps its `models.roles` tier and never the frontier tier (WORKFLOW § `models`).
- **Never commits without Conventional Commits body and `Hatsu-Agent: Kurapika` trailer**.
- **Never leaves delegation open** — say when it ends.
