# Backlog board — the same board, painted

**Nature: Manipulator.** The board-facing half of the work.

[`backlog-state`](../backlog-state/SKILL.md) answers *"what is at my gate right now, and what does
each thing need from me?"* as a markdown table. **This skill answers the identical question with the
identical computation and paints it as a Rikugan page.** No second source of truth.

> **Read-only, without exception.** Inherited from `backlog-state`. If reading the board makes the
> next action obvious, **say what the action is on the board** — do not take it.

## 1. Invocation

```
/backlog-board <backlog-state's § 1 line> [every <turn | state-change | once>]
```

```bash
nen parse backlog-board --grammar '<backlog-state § 1's template, substituted> [every <freq:turn|state-change|once>]' --line '<the invocation>' --json
```

**Everything before `every` is [`backlog-state`](../backlog-state/SKILL.md) § 1's grammar, verbatim
and read there** — the subject (`context` included), the `@` selector, the `#` labels, every refusal,
the `alternative`/`items` reading, the quoting and the no-token rule. Each repository is its own page. A missing argument or configuration item is
asked for and set up inline (`missing-argument`, `missing-configuration`;
[`WORKFLOW.md`](../../../../docs/WORKFLOW.md) § 4).

## 1a. Rendering frequency

The clause controls **how many times this session loops through §§ 2–4** for the scope; it changes
nothing computed.

- **`once` (default, and what an omitted clause means).** Sweep, render, publish, say the line, stop.
- **`every turn`.** Re-run §§ 2–4 before each subsequent maintainer message, republished to the
  **same** URL. Echo the parsed mode before the first render; a later re-render that changed nothing
  is silent.
- **`every state-change`.** The same loop gated on `nen board diff` (§ 2a), never on a by-hand field
  comparison. Before the first poll, echo the mode, the interval and what counts as a change —
  exactly the fields `board diff` compares: `gate`, `status`, `needs`, and a row entering or leaving
  the scoped set. Only after that echo does *nothing moved ⇒ no render, no line* apply.
- Both repeating modes borrow [`izanami`](../izanami/SKILL.md)'s loop discipline: no iteration cap
  (nothing here writes), one line per render, the loop in the session — no timer, no cron.
- **What ends it:** the maintainer says stop, moves on, invokes this skill again, or the session
  ends. A frequency mode is **session-scoped**, never standing.

## 2. Compute the picture

Follow [`backlog-state`](../backlog-state/SKILL.md) end to end for **everything about what the rows
are**: the repo set, `nen backlog fetch` / `nen backlog order`, the gate (`nen gate derive` composed
with `nen pr ready`'s verdict), status colour (`nen color status`), the expected-action line, session
· lane, and ordering. **Nothing about the computation changes because the output is HTML.**

Then the object rows, from the verb that owns them:

```bash
nen report data --repo <path> --base origin/<branch.base> --target <owner/name> --backlog [§ 1's filter flags] --json  # --base required
```

`context` passes `--prs`/`--issues` for its echoed list in place of `--backlog`.

`objects[]` is one row per open issue and PR:
`{ kind, number, title, url, state, labels[], head, mergeStateStatus, checks{}, threads{},
reviewRequests[], linked[], readiness{verdict,reason,source} }`, with `readiness` read from the head
SHA's `readiness` check where there is one, else computed from the in-process gate, else `null` with
the reason on stderr. `nen board build --repo-slug <owner/name> --rows-from <path>` assembles the
same rows into a `Board` for the diff; it fetches nothing and derives nothing itself.

## 2a. `nen board diff` — the state-change engine

`nen board diff --before <path> --after <path>` is a **field-level diff of two Board snapshots by row
id**; `every state-change` runs on it. A null diff is `{"rows": [], "changed": false}`. A malformed snapshot is **refused at exit `2` naming the file,
row and field**, never diffed — a caller bug in the § 2 mapping: fix the row and re-run.

**`nen watch until` cannot drive this poll** — a fetch → `board build` → `board diff` chain is three
programs and its shell-less `--command` refuses it. The loop runs at the session's own pace.

## 3. Render — the Rikugan, never hand-authored HTML

The page is [`templates/rikugan.html`](../../../../templates/rikugan.html), filled by the verb — and, where the
surface's report is a Markdown artifact, [`templates/rikugan.md`](../../../../templates/rikugan.md) from **the same
data document**, `--out <reports.dir>/current.md`, copied verbatim
([`PROCESS.md`](../../../../docs/PROCESS.md) § *The Markdown report*):

```bash
nen report render --variant register --template templates/rikugan.html \
  --data <the data document> --out <reports.dir>/current.html --repo <path> [--graph <file>]
```

The variant's blocks come from `reports.sections.register` in `nen/workflow.json`,
injected as presence flags before the fill. **The
data document is the verb's, never hand-built** (zheref/hatsu#221, zheref/nen#276):

```bash
nen report data --repo <path> --base origin/<branch.base> --target <owner/name> --backlog \
  [§ 1's filter flags] --register <desk.json> --json > <the data document>     # a repository scope; an object scope passes --prs/--issues
```

`<desk>` is the judgement half you compose and nothing else; its shape is `nen report data --help`'s
(`--register`), its rules and a minimal example in [`PROCESS.md`](../../../../docs/PROCESS.md) § *The report data document*. **Every fact is nen's**: each row gains its `notation`, `verdict`,
`labelsLine`, `checksLine`, `threadsLine`, `linkedLine` and `head`; the tallies, `footerCount`,
`spendEfforts[]` and the empty graph keys are added after `objects[]`. **A verdict is quoted, never
written**: a desk carrying a `verdict` at any level — or any key nen does not read — is refused at exit
`2`. A gate-filtered page passes its gate-matched objects as `--prs`/`--issues`, so the tallies count
only them; nen's tallies never read a gate. The five tallies, as nen 0.22.0 counts them: **`tallyScope`** — the objects in scope;
**`tallyNeedsYou`** — the asks across every gate; **`tallyBlockers`** — open PRs with a red check, an
unresolved thread or a `DIRTY` merge state; **`tallyReady`** — open PRs whose verdict is `ready` and that
are not blockers; **`tallyInFlight`** — the remaining open PRs. The keys the template reads are the
document's; `nen report render --dry-run` lists every token a template names.

Keys and values follow [`PROCESS.md`](../../../../docs/PROCESS.md) § *Escaping and validation of report
data* — **every `url` field** included. The four `…Line` strings are
flattened for display, so an issue row and a PR row carry the same keys; `notes` is the row's free
lines and is `[]`, never absent, when there are none. The desk builds no spend row: `spendEfforts[]` is nen's,
from the ledgers and the desk's `efforts?`/`spendNotes?`. `notation` and `footerNote` follow [`PROCESS.md`](../../../../docs/PROCESS.md) § *Publishing a
report*.

**The desk is the board's point.** Asks grouped by gate then ranked by unblocking power, each opening
`DECIDE`, `DO` or `MERGE`, each carrying lettered options with **exactly one star** — the same list,
same order, same letters the surface's own picker will show. **A gate with nothing owed is rendered
cleared, not omitted.** The page briefs; the picker asks.

**A drawing is optional.** Where the scope has a shape worth seeing — a chore's PR graph, an epic's
child tree — pass a `nen.report.graph/v0.1` document as `--graph`; otherwise `graphNodes` stays
empty and the block does not render.

## 4. Publish it

An **Artifact** titled *Gate Register*, **one URL per repository**, published as
[`PROCESS.md`](../../../../docs/PROCESS.md) § *Publishing a report* says — a page that moved means the
backlog is re-resolved, never repainted from what this session holds. **Say the one line in chat and
stop** — the subject and every filter, the count needing him, the link.

## 5. Not a gate event

A requested board is not a gate event ([`PROCESS.md`](../../../../docs/PROCESS.md) § *Reporting a
phase*), **on every repeat** too; a board that makes the merge obvious is still not a reason to act.

## 6. When the pipeline cannot run

`nen report render`, `board build` or `board diff` unavailable (nen out of range is
`ten`'s D10 contract), or the `backlog-state` sweep
failing for its own reasons: **relay it in one line, then fall back to `backlog-state`'s markdown
table with the same arguments**, saying so. Inside a repeating loop the same failure **ends the
loop** — one fallback pass, then stop; it never retries blind.

## Hard limits

Everything in `backlog-state`'s own never-list, plus:

- **Never hand-authors the page.** § 3 is a verb call over a fixed template; only a rendered page is
  checkable.
- **Never publishes a board whose rows came from session memory** rather than a fresh sweep, on any
  render.
- **Never fires the banner, `nen stop` or a push notification** for a requested board.
- **Never silently substitutes the markdown table** when the pipeline failed.
- **Never diverges from `backlog-state`'s grammar or classification** while advertising them as one.
- **Never re-derives "what changed" by eye** in `every state-change` mode (§ 2a).
- **Never runs a repeating mode with no stated pace, echoed frequency or way to end it**, or carries
  one past its session.
- **Never omits a cleared gate from the desk**, and never renders an ask without a starred option.
- **Never writes outside `<reports.dir>`**, and never gives a `register` render a dated file — only
  `final` gets one.
- **Never labels, merges, pushes, comments, opens or closes anything.**
