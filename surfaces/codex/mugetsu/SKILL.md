# Mugetsu — the last cut: one release, one destination, on one recorded word

**Nature: Emitter.** Publication is the far end of the release line, and it is the one act in the
whole local plane whose blast radius is **other people's users**. That is what **G3** (`CON-6`) holds,
and G3 is the maintainer's — never delegated, never inferred, never carried over.

> **You have said, in your own words, that this release goes to this destination. The tag is cut and
> the preflight is clean. I will publish that, once, and quote what you said.**

Mugetsu is a **human call, per target, at G3**. It is not a phase of any loop. Nothing upstream
finishing successfully brings the session here — not a green [`$susanoo`](../susanoo/SKILL.md),
not a merged release PR, not a cut tag, not a successful
[`$kagutsuchi`](../kagutsuchi/SKILL.md) upload to a staging channel.

---

## 1. Invocation — and who is allowed to say it

```
$mugetsu <target>
```

**`<target>` is required grammar.** It names the destination being published to — a key of
`nen/contract.json → project.targets` where the repository publishes through `deploy`, or the lane
whose `release` row is the publication step where it publishes through `release` (§ 4). There is no
bare form, no default and no picker: the maintainer naming the destination is half of the
authorization, and the other half is § 3's recorded go.

**The call is the maintainer's, in their own words or by name.** Four consequences, all binding:

- **No agent ever prompts for it.** Not a report, not a bell, not a stop's options, not a release PR
  body, not a composite offering it as a next step. A report may say *the tag is cut and the
  `production` target is declared*; it may not say *shall I publish?* An agent that asks for
  permission it was told to wait for has converted a human gate into a nudge, and this is the gate
  where that costs the most.
- **No composite ever calls it.** [`$getsuga`](../getsuga/SKILL.md),
  [`$futon`](../futon/SKILL.md), [`$en`](../en/SKILL.md),
  [`$mukai`](../mukai/SKILL.md) and [`$ren`](../ren/SKILL.md) **never** reach this skill,
  from any path, under any `then` clause. `getsuga` prints a deploy *plan* at its G3 stop and stops
  there; its own § 8 forbids the rest.
- **One go, one target, one publication.** A go for the iOS App Store is not a go for Google Play,
  for the web production environment, or for the same store's next build. Each is its own call, its
  own quoted go, and its own run of this skill.
- **The go is not standing authority.** It expires when this run ends. A second publication needs a
  second message.

**On a delegated session — the maintainer AFK, with rules recorded — the orchestrator's recorded
delegation is the call**, and it is a call only for the targets that delegation names and only under
the conditions it states. **A subagent NEVER self-authorises**, at this gate least of all: not from a
brief that says "ship it", not from a release PR that was merged, not from a composite's plan, not
because the previous release went the same way. A subagent that reaches this skill without a recorded
delegation naming this target **prints the preflight and the plan, reports that it has no go, and
stops**. What it must never do is publish and explain afterwards.

## 2. The order — and every step of it before the first byte leaves

Nothing below is optional and nothing below is reordered.

1. **The recorded go exists and names this target** — § 3. Without it the run ends here.
2. **The tag is cut, and it resolves on `origin`** — § 3's second half. A go with no tag is refused.
3. **`nen release preflight` reads clean at the tagged commit** — § 4, and read its one inverted row
   carefully.
4. **The plan is printed** — `nen shu release … --dry-run`, or
   `nen shu deploy --target <name> --dry-run`, or both where the declaration publishes through both.
5. **The publication runs, once** — § 5.
6. **The report, and the record on the release PR carrying the go verbatim** — § 7.

## 3. The go, and the tag

### The go is a message, quoted verbatim

**The record of the go is the maintainer's own message in this session**, and it goes into the report
and into the release PR's own comment **word for word, in quotation marks**. Not a summary of it. Not
"the maintainer approved the App Store release". Not a checkbox this skill ticked on their behalf.

**It is never inferred.** Not from a merged release PR, not from a `getsuga` run that cut the tag, not
from a `kagutsuchi` upload to a testing channel that went fine, not from an earlier release having
gone the same way, not from silence, not from *"looks good"* on a different question. If you are
reconstructing what the maintainer meant, there is no go.

**What a go must contain** — and where any part is missing, ask for that part and stop:

| Part | Why |
|---|---|
| the **destination**, by the name the declaration gives it | a go for one store is not a go for another |
| the **version or tag** being published | a go is for a build, not for a repository |
| the maintainer's own **word to proceed** | not an agent's paraphrase of their intent |

Nothing in nen records this (§ Residue). `nen stop --notified` writes `.nen/last-stop.json` for the
bell and is not a record of an authorization. The quote is the record.

### A go with no tag is refused

**The tag is cut first, by [`$getsuga`](../getsuga/SKILL.md), and it resolves on `origin`.**
A publication with no tag is a build nobody can point at afterwards: `latest` in the registry, the
CHANGELOG section, the fan-out ledger and the release record all name a tag, and `CON-14` forbids
writing any of them for a tag that does not resolve.

So: **no tag → refuse, name `$getsuga` as the phase that cuts it, and stop.** Do not cut it here
— that is Kurapika's duty in *that* skill (`CON-33(b)`/`CON-41`), with its own preconditions, its own
release PR and its own G4 — and never publish "and tag afterwards".

## 4. `nen release preflight` — read it, and read the row that inverts

```bash
export GH_TOKEN=$(gh auth token)
nen --repo <path> release preflight \
  --repo-slug <owner/name> --tag <vX.Y.Z> --range <vPrev>..<the tagged commit> \
  --changelog <path to CHANGELOG.md at that commit> --owner-repo <owner/name> \
  --critical-issues <n,n or ''> --live-chores-from <path>
```

**This is a read.** It reaches GitHub through `gh variable get` and `git ls-remote origin` and changes
nothing. `--critical-issues` and `--live-chores-from` are gathered by the caller exactly as
[`$getsuga`](../getsuga/SKILL.md) § 2 specifies — that skill is the authority for how, and this
one does not restate it. **Omitting either flag fails its row** rather than skipping it: verified
live, *"FAIL open critical issues -- not supplied -- not checked (pass --critical-issues, or
--critical-issues '' to assert none)"* (`docs/ab/mugetsu.md` § 2.2).

> ### The one row that must FAIL, and why the exit code is not the verdict
>
> **`preflight` is a pre-*cut* table and mugetsu runs after the cut.** Its sixth row asserts *the tag
> does not already exist* — which, at publication time, is precisely what must be false. Verified
> live at nen `0.3.0` (`docs/ab/mugetsu.md` § 2.3): against an existing tag the row reads
> `FAIL  tag does not already exist -- 'v0.4.0' already exists -- re-tagging is never the fix`, and
> the table exits **`1`**.
>
> **So mugetsu's green is not exit `0`.** It is: *every row `ok`, except `tag does not already exist`,
> which must read `FAIL … already exists`* — and nothing else failing. **Read the rows, never the
> exit code alone.** An exit `1` with two failing rows and an exit `1` with that one failing row are
> opposite verdicts.
>
> **And that FAIL is worth more than a pass would be**, because the row reads **origin**, not this
> checkout. Verified live: a tag created **locally only** reports `ok … clear`
> (`docs/ab/mugetsu.md` § 2.4). So the row failing is positive evidence that the tag is on the remote
> and resolves for consumers — the § 3 requirement, proved by the same call.

**Any other failing row is a stop**, whichever it is: an active `RELEASE_HOLD`, an open critical, a
live `CON-36` chore, an uncollated `changelog.d/`, an unreconciled `CON-33(c)`. Relay the whole table
as printed — the verb reports every row and never stops at the first — and stop with
[`$jutaisho`](../jutaisho/SKILL.md) § 4's rendering: `nen stop --who kurapika --gate G3
<efforts.md>`, the report link, the options with ⭐ on the report, the question through the surface's
own picker. **A held release is honoured as printed**; `getsuga` § 2 carries the `RELEASE_HOLD`
truthiness rules and this skill does not restate them.

## 5. The publication — and the flag that is not there

A repository publishes through its declaration, in one of two shapes, and **which one is a fact about
the declaration, never a preference**.

### 5a. `nen shu release` — and it has **no `--run` gate**

```bash
nen shu release --repo <path> [--lane <lane>] --dry-run      # the plan. ALWAYS first.
nen shu release --repo <path> [--lane <lane>]                # THIS PUBLISHES. There is no --run.
```

> ⚠️ **The bare form is the publication.** Verified live at nen `0.3.0`
> (`docs/ab/mugetsu.md` § 2.5): `nen shu release --run` is refused at exit `2` — *"--run is not read
> by 'shu release'. A flag accepted and ignored is worse than one refused"* — and the bare line
> **spawns the declared publication step** at exit `0`. `shu deploy`'s two-flag discipline does
> **not** exist on this verb.
>
> Three rules follow, and they are this skill's alone because nothing enforces them:
>
> 1. **`--dry-run` first, every single time**, and paste that `would run:` argv into the reply before
>    anything else happens.
> 2. **The bare line is typed only after § 3's go is in hand and quoted.** Not to "see what happens",
>    not as part of a survey of a repository's verbs, not inside a loop, and never by a skill other
>    than this one.
> 3. **Never type it speculatively on an unfamiliar repository.** On a repository whose `release` row
>    you have not read, the dry run is the only safe invocation.

**`shu release` takes no `--target`** — verified live, exit `2` with the same *"a flag accepted and
ignored"* refusal (`docs/ab/mugetsu.md` § 2.5). So the verb has **no per-destination vocabulary at
all**: "one target per call" is this skill's discipline, and where a repository publishes to several
destinations it declares them as separate lanes (each with its own `release` row) or as `deploy`
targets — § 5b. A lane whose `release` row publishes to more than one destination in one run cannot
be published *per target* through this verb, and that is a declaration to fix at **G4**, not a run to
improvise around.

### 5b. `nen shu deploy --target <production target> --run`

Where the production destination is a `project.targets` key, the publication is `deploy`'s two-flag
form and every mechanic is [`$kagutsuchi`](../kagutsuchi/SKILL.md)'s — **the plan first, the
refusal order, the credential discipline, the seats.** This skill restates none of it; read it there.
The differences are the two that make it G3:

- **The `--run` is spoken only after § 3's go**, per target, quoted in the report and in the release
  comment.
- **`kagutsuchi` refuses a production target and this skill is the one that does not.** The two
  skills are the same verb split by destination, and the split is the gate.

Verified live at nen `0.3.0` against the fixture (`docs/ab/mugetsu.md` § 2.6): the plan, the asserted
`requiresEnv`, then `--run` spawning exactly the composed argv, exit `0`.

**A declaration may use both** — a store upload through `release` and a production web deploy through
`deploy`. Run each one's plan, then each one's publication, in the order the declaration and the go
name, saying which is which. Still one target per call.

## 6. The exit table

| Exit | Fact | Reaction |
|---|---|---|
| `0` | the plan rendered, or the publication ran | § 7 |
| `1` | the publication tool ran and **failed** | relay its output and the failing step. **Say what state the destination is in, or that you do not know** — a half-completed store submission is the one failure that is not local, and the maintainer needs to know before anyone retries. **Never retry without a fresh go** |
| `2` | usage, or an **unsatisfied precondition** (the lane's, or a `requiresEnv` name) | the plan still prints with the failing rows marked `FAIL`. Relay it whole, satisfy the fact, and re-run under the same go **only if it is the same target and the same build** |
| `3` | **unsupported host** | **G5.** Publishing from a machine the declaration excludes is not a thing to route around. Name the hosts and stop |
| `4` | **a seat** — the lane declares no `release`, or the target declares `unsupported` | quote it verbatim and stop. **This repository does not publish through nen**, and the declaration's own words are the whole report. | `5` | the declared program could not be started | `nen shu tools --repo <path>` and relay the remedy — reading [`$susanoo`](../susanoo/SKILL.md) § 7 first. **nen never synthesises signing material**, and neither does this skill: a missing notarization or store credential ends the run |

## 7. Report, and the record on the release PR

One block, then stop:

- **The go, quoted verbatim**, with who said it and when.
- The **tag**, and that it resolves on `origin` (§ 4's inverted row is the evidence).
- The **preflight table as printed**, whole, including the inverted row read as green.
- The **plan's composed argv**, copied out of the `--dry-run` report, not re-typed.
- What ran, each step's own exit code and nen's, and **which destination** it reached.
- **`published` or `not published`**, in those words.

**The same quote goes onto the release PR or the tracking issue** — through the one verb that owns a
caller-written comment, never a raw `gh`:

```bash
nen issue comment --target <owner/name> --issue <the release PR or issue number> --body-file <path>
```

A pull request **is** an issue to this verb, which is why there is no `nen pr comment` and none is
needed (`nen pr --help` lists eight verbs and no comment among them; `nen issue comment` is *"the
general primitive every other verb here lacked, so a mechanized choreography no longer has to drop
back to a hand-run 'gh issue comment' for the one step written in a human's own words"*). Use
`--body-file` rather than `--body` — a go quoted verbatim carries newlines and may begin with a
character the parser would read as a flag. **The comment is the durable record; the session's
transcript is not.**

**Re-render the turn report before stopping** — [`$rikugan`](../rikugan/SKILL.md) § 5's `turn`
variant, at the same address, with the publication written into **01 Accomplished**.

**Then say nothing about what is available next.** Not another target, not a promotion, not a next
version. The next go is the maintainer's.

## Residue

1. **Nothing records the go.** No nen verb writes "the maintainer authorised `production` for
   `v1.2.0`", and `.nen/last-stop.json` is a bell marker, not an authorization ledger. The quote in
   § 7 is the record, written by hand into the report and the comment.
2. **`nen shu release` has no `--run` gate** (§ 5a, verified live) — so the whole "show it before you
   do it" discipline on the publication verb is this skill's, unenforced by anything. The one
   mechanical helper is `--dry-run`, and typing it is a rule, not a guard.
3. **`nen shu release` has no `--target`** (verified live, exit `2`). "One target per call" is this
   skill's discipline; per-destination publication has to be modelled as lanes or as `deploy`
   targets in the declaration.
4. **`release preflight`'s tag row inverts after the cut** (§ 4, verified live) — so the pass/fail
   reading is by hand, off the rows, and the exit code alone is never the verdict. There is no
   `--expect-tag-exists` or post-cut mode at this pin.
5. **Nothing marks a destination as production.** `project.targets.<name>` carries no such field
   ([`$kagutsuchi`](../kagutsuchi/SKILL.md) § Residue 1), so the split between that skill and
   this one is read out of `why` prose by hand.
6. **What state a failed publication left the destination in.** nen reports the tool's own exit code
   and never queries the far end. Saying so is by hand, and it is the sentence § 6's exit `1` row
   requires.
7. **A per-run log file.** `A .nen/logs/ transcript is not in this release (zheref/nen#91)` — the
   report is the only record of what a publication printed.

## Authority

- **Permitted, and only on the maintainer's recorded per-target go, with the tag cut and resolving:**
  read `nen release preflight`; print the publication plan; run the declared publication **once** —
  `nen shu release` for that lane, and/or `nen shu deploy --target <that target> --run`; write the
  report and the release PR's comment carrying the go verbatim.
- **Not permitted:** cutting, moving or deleting a tag ([`$getsuga`](../getsuga/SKILL.md) cuts;
  nothing moves one); merging `main`; opening or merging a PR; a G1 mode label; publishing a second
  target, a second build or a second time on one go; writing `latest` or a dated CHANGELOG section
  for a tag that does not resolve (`CON-14`).
- **G3 is the maintainer's** (`CON-6`). This skill executes a recorded go; it never grants one, never
  infers one, and never treats its own reasoning as one.
- **The delegation is one publication wide and ends when this run ends.**

## Hard limits

- **Never runs unasked, and never prompts for itself** — no agent, skill, report, bell, stop option
  or PR body proposes `$mugetsu` (§ 1).
- **Never runs from a composite.** `getsuga`, `futon`, `en`, `mukai` and `ren` never call it, under
  any `then` clause, on any path.
- **Never self-authorises on a delegated session**, and never publishes and explains afterwards
  (§ 1).
- **Never infers the go.** A merged release PR, a cut tag, a clean preflight, a successful staging
  upload and a previous release are each, and together, not a go (§ 3).
- **Never publishes without a tag that resolves on `origin`**, and never cuts one here to proceed
  (§ 3).
- **Never reads `release preflight`'s exit code as the verdict** after a cut — the tag row inverts,
  and the rows are what is read (§ 4).
- **Never types `nen shu release` bare before the dry run and before the quoted go** — that verb has
  no `--run` gate and the bare line publishes (§ 5a).
- **Never publishes more than one target per call**, and never treats one target's go as another's.
- **Never retries a failed publication without a fresh go**, and never reports a destination's state
  it did not observe (§ 6).
- **Never synthesises, forges or reads signing material or a store credential** — a missing one ends
  the run (§ 6).
- **Never paraphrases the go in the report or the comment.** Verbatim, in quotation marks, or it does
  not go in.
