### Changed

- **Every Futon-based batch drives every delivery to Ready, or holds it and names why (zheref/hatsu#488).** `docs/WORKFLOW.md` § *Batch delivery* states the maintainer's instruction of 2026-10-25 once. `en` is started behind every delivery a batch opens and keeps acting on pending checks, owed review rounds, findings and catch-up. Every delivery stands in exactly one state — `driving`, `ready` (the `nen pr ready` verdict quoted at the current head), `merged`, `closed`, or `held-<cause>` (approval, gate — en's sixth stop and hanten prompt included —, credential, cap, handback, stranded), parked durably with `nen run park` (a later merged or closed read wins over the append-only park) and carrying three facts: the prerequisite or bound, the last verdict and its judged head, the resume line. A batch with any held delivery ends **incomplete**, never as a success, `register` not `final`; an attended run stays open while a delivery stands Ready at its prompt; the wrap-up picker waits for the run's end. Under `--idle` a run has one integration branch and one integration-to-main PR, no per-effort PR and no stack; an effort that cannot join parks and is listed not included; separate integration deliveries come only from separate runs. `hatsu:futon` §§ 1, 10, 12, `hatsu:kazaana` §§ 1, 3, 7, `hatsu:en` § 7, `hatsu:dowsing-chain` § 9 and `hatsu:backlog-loop` § 10 cite it; no batch ends on "blocked" any more, and WORKFLOW's stacking default and idle overlap rule now say *attended*.
- **`scripts/futon_effort_record.mts`** gains `resume` — the newest real, unended run typed as the same line, or `--run <id>`, continued under its own id with the launch answers nen stored (re-checked against the idle floor), its recorded terminal and integration branch; exit `3` alone means *no open run, start one*, every refusal is exit `1`; it refuses before calling nen when the manifest is absent (nen would write an empty one that opens the `then` gate), and a moved committed profile is reported, never obeyed — `end`, which futon § 10 records so a finished run is never resumed, and `integrate`, which records the run's one integration branch and refuses a second one, the default branch in any spelling and a name `git check-ref-format` rejects. A malformed or forged sibling record never refuses a start and never is picked. `bind` refuses an idle run, `verify` refuses a claim on an idle or dry run, and `start` names an earlier run typed as the same line. The fixture's stub nen now keeps manifests as nen 0.28 does, and it asserts that the batch endings in futon, kazaana and backlog-loop cite § *Batch delivery*; it is red against the previous script and the previous futon prose.
