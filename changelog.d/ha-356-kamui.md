### Added

- **`hatsu:kamui` — one feature written once as the product's spec, then ported to the siblings you pick** (plugin `0.125.0`; zheref/hatsu#356, child 2 of the cross-platform porting epic zheref/hatsu#354). `hatsu:kamui <CODE>-IS-#<N> | <CODE>-PR-#<N> [--dry-run]` writes the source issue (or a shipped PR and its closing issues) as a `github/spec-kit` set in the product family's **spec repository**: pinned at `v1.2.2`, read live on 2026-10-20, it writes `specs/<nnn>-<slug>/` with `spec.md`, `plan.md`, `research.md`, `data-model.md`, `quickstart.md`, `contracts/`, `tasks.md` and `checklists/requirements.md`, plus `.specify/memory/constitution.md` once, which cites `CON-{n}` and never overrides it. The spec repository is searched for the source first, so a second run amends the folder. The spec PR runs `ren → aka → mukai → en` to the **G2** merge prompt. Nothing is built before it merges: the wait is `nen watch until` on the PR's state, and `CLOSED` ends the run as *spec declined*. Then the sibling picker (new `nen/decisions.json` row `port-siblings`) asks which configured siblings get a port issue. It is never starred, pages in fours and asks even for a lone sibling; its answer is the G1 for one port issue per pick through `file` §§ 3–5, written by `nen issue file` and read back explicitly. A start picker then runs the picks as `hatsu:build` one after another. `hatsu:kamui resume <run-id>` continues from `${XDG_STATE_HOME:-~/.local/state}/hatsu/ports/<run-id>.json` in any checkout. The two grammars are separate `nen parse` templates chosen by the literal first token. Missing setup is asked per item; creating the spec repository is a G5 hand-over line.
- **`families[]` and the `spec` role, documented on the Hatsu side** — `docs/config/repos.json.md` § `families[]`, with redacted fixtures (`scripts/fixtures/port-family/`, with and without a family) that read `ok` through `nen schema check` at nen `0.22.0`. A family is declared only in its members' and spec repository's own registries, never in Hatsu's. The nen half is owed: zheref/nen#453 (the key and the role) and zheref/nen#454 (`watch until --until merged`); nen's prose pack (zheref/nen#450) and `idea file`'s ignore file (zheref/nen#444) are cited. The `<fixture-*>` placeholders join `docs/PUBLIC-REDACTION.md`'s legend.
- **A ninth catalogue domain, `port`**, with `workflow.port.specKit.pin` (`v1.2.2`) and `workflow.port.specKit.layout` (`specs/{nnn}-{slug}`), in WORKFLOW § 2 → `port` and `docs/config/workflow.json.md`. `config_values.sh need --skill kamui` reads *every value it needs is set* on both fixtures.
