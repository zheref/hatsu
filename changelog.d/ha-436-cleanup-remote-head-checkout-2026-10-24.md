Now every remote-head row outside the clean effort-worktree sequence, deterministic or proposed, names its host. That includes a merged head whose worktree is kept: dirty, locked or not admitted. The row first reads `git ls-remote --heads origin -- '<branch>'`, which must print the SHA pass 1 recorded, else the row runs nothing and is reported. Then it runs `git -C '<host>' push origin --delete -- '<branch>'`, where `<host>` is a literal path: the head's own worktree when § 4's admission admitted it, else another admitted path. An admitted path is never on `<branch.base>` (condition 6 of `cleanup_path_admit.ts`'s header), so the trunk guard lets the push through, and core is never the host. The host goes in the row's evidence. Every push runs before any `worktree remove`, and § 6's pass 2 says so ("every push first"), so the host is still there when its row runs. With no admitted path, the row is **named** (`no admitted checkout`, now in the "Named facts win" list) and never given a command that cannot run as written.
