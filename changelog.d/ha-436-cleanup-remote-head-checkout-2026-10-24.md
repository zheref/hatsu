### Fixed

- **`cleanup` names the checkout a remote-head delete runs from when no worktree is left (zheref/hatsu#436).** § 5 had a push shape only for an effort worktree, so on the HA-IS-#426 sweep a merged remote head whose worktree was gone got a row pushing from core, which sits on the trunk and is refused by `hooks/guard-base-branch.sh`. Now a remote head with no worktree, in any class, pushes from a host: `git -C '<host>' push origin --delete -- '<branch>'`, where `<host>` is a literal path § 4's admission admitted. An admitted path is never on `<branch.base>` (condition 6 of `cleanup_path_admit.ts`'s header), so the trunk guard lets the push through, and core is never the host. The host goes in the row's evidence, and every push runs before any `worktree remove`, so the host is still there when its row runs. With no admitted path, the row is **named** (`no admitted checkout`) and never given a command that cannot run as written. `agents/shizuku.md` restores the push-before-removal ordering #435 took out of § 6 and names the host. To stay under the 12288-byte ceiling, cleanup drops § 4's prunable/surface clause (the admission header refuses both), the `(-D)` gloss in § 6, the Hard limits' repeat of § 4's name rule and § 5's proposed restatement of the stale-trunk `git branch -d` case (the deterministic clause keeps it).
