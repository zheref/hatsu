### Changed

- **Step one of the CI nen-digest check: the workflow-policy validator learns the digest step that sits beside each bootstrap, and the bootstrap form that goes with it** ([#230](https://github.com/zheref/hatsu/issues/230)). The validator judges every pull request from the base, so the step is registered one PR before the live workflows take it. Beside the digest step the bootstrap no longer runs the binary: `nen --version` moves into the digest step, after the match, and a bootstrap that still prints the version beside it is refused as the old order. The frozen body tests the contract before reading it, fails a hash it cannot take by name, and reads the value whole, so a trailing newline cannot pass as a digest; it is proven under bash against a scratch binary and contract, eleven cases per body, the binary running only once it matched. Where the root holds `templates/pr-readiness.yml` (Hatsu itself), tenkai's rendered readiness form is refused, so no pull request can trade the checked bootstrap for the consumer's. No workflow, contract or shipped surface changes in this step.
