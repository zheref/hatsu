### Changed

- **The three inputs every Hatsu PR hands nen are declared once, in `contracts/pr-composition.json`** ([#171](https://github.com/zheref/hatsu/issues/171); the nen half is zheref/nen#239). Until now each run retyped them from prose. **Body check:** `contracts/pr-body.requirements.json` is the `{name, pattern}` array `nen pr body-check --requirements-from` reads, derived from `templates/pr-body.md` — eight required headings, `The flow` and `Economics` optional, `## Agent attribution` required last — and `shibari` § 4 passes it from `$hatsu_root`. **Gate sets:** `gateDerive."zheref/hatsu"` holds the two `nen gate derive` path sets, its process set now carrying `contracts/` and `templates/` so the declaration, the array and the template derive `G4` as `docs/WORKFLOW.md` did when it held the sets (this run's reading, the maintainer's to confirm at the `G4` merge); a canon repository with no row has none declared, the run asks, and the row is written by a Hatsu PR at Hatsu's `G4`. **Fragment inputs:** `changelogFragment` holds `fragment-required`'s `specPaths`, `fragmentDir` and `headChangelog`; a PR that adds its `changelog.d/` fragment reads `fragment-present` with no opt-out line, and `directSection.optOut` is the one opt-out, carried only by a PR whose own diff changes `CHANGELOG.md`. That condition is unenforced by nen, which honours the phrase anywhere, over any diff, inside an HTML comment or a code fence too: a Hatsu-side raw-body check is owed, and the nen half is zheref/nen#239's scope. **Citations:** `docs/WORKFLOW.md` § *Gate derivation*, `shibari`, `tensho`, `jujisho`, the template and `CONTRIBUTING.md` cite the file and carry no copy. **Drift guard:** `scripts/pr_composition_check.sh`, the new `pr-composition-guard` lane (35 fixture cases), fails on a literal set copied into the canon prose (a leading `/` included), a Gate derivation section naming a directory prefix of any depth that no declared set carries or a file path no set covers (the section cut with fenced lines masked), a requirements array that drifts from the template, the fragment opt-out phrase anywhere in the template, a reader that does not cite the declaration, a declared path that escapes the root, and a scanned file that is not UTF-8. **Template hazard:** the template's top comment no longer spells out the fragment opt-out phrase, which nen honours anywhere in a body.
- **`scripts/plugin_bump_check.sh` no longer honours `no plugin bump:` over a shipped path** ([#171](https://github.com/zheref/hatsu/issues/171)). The line used to skip the version check for any diff — HA-PR-#233 carried one over `docs/WORKFLOW.md` and `nen/contract.json` and passed. It is now accepted only where no `PLUGIN_SURFACE_GLOBS` path changed, and, when the version is not bumped, refused by name otherwise, listing the shipped paths; beside a bump it is inert and the pass line says it was ignored; the script header, `CONTRIBUTING.md`, the README, `getsuga` § 3 and `docs/ab/plugin-bump-guard.md` say the same. The required check runs the trusted revision, so the rule binds PRs opened after this merges. Plugin bumped to 0.101.0; mirrors regenerated at that stamp.
