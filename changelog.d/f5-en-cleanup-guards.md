### En pre-push PR-state guard, carrying-PR ledgers, and cleanup open-base protection

- **En pre-push PR-state guard (`zheref/hatsu#611`)**: Added `scripts/en_push_guard.mts` (focused lane `en-push-guard`), a **prose-ordered precondition** of En's push that `en` § 3 runs before every push (`murasaki` and `scripts/publish_gate.sh` are unchanged). It reads live state through the existing `nen pr fetch --target <owner/name> --pr <N> --json` and exits `0` (open, head matches: push), `1` (`MERGED`/`CLOSED` with commits to carry: the carrying-PR fallback), `2` (unread state, an open PR with no `headRef`, or an unread carry list), `3` (open PR on another head: a stop handed back) or `4` (`MERGED`/`CLOSED`, nothing unpushed: `en` § 6's terminal rows). The carry set is the push En was about to make: non-merge commits past the PR's last pushed head and not already on `origin/<base>`, so a closed PR carries only when a push is pending; a post-push `--require-head <sha>` re-read (one, paced) runs the same carry log and routes anything past the PR's head to the fallback. A deleted base is the one case where `--base` is `<branch.base>` rather than the PR's `baseRef`: the successor passes `--carry-from base` to carry the child's whole unlanded set, an unmerged deleted base ends the run, and En's own unread timeline or branch reads are a stop handed back. `en` § 6 is keyed on those exits, the base-deletion successor included, so no push ever reaches a merged or closed PR's branch; the successor PR is raised to `hanten`, whose § 2b keys its ledger to `--pr <successor-N>`.
- **Cleanup open-PR base protection & merged-ahead evidence (`zheref/hatsu#616`, `zheref/hatsu#611`)**: Added `scripts/cleanup_plan_guard.mts` (focused lane `cleanup-plan-guard`) and updated `cleanup` §§ 4–6 and `shizuku.md`. `base of open PR` outranks cleanup's table across remote heads, local branches and worktrees (`named`, never deterministic); every remote-head row records `base of open PR` in its evidence; `classify` refuses a missing, invalid or truncated (1000-row) input at exit `2`, and a worktree is deterministic only on an explicit admitted, unlocked read; `pre-delete` binds `--target` to every fetch and push URL of the checkout's origin (refusing, without echoing it, an origin with embedded credentials; both guards redact userinfo up to the last `@` and in percent-encoded form), requires `--base` and a `headRefName` on every open-PR row, refuses an open PR's base or head, and prints the plain `push origin --delete`, prefixed `env -u` with every scrubbed git variable so an exported `GIT_DIR` cannot redirect it, to run at once (no lease: the permissions pack denies `--force-with-lease`, so the check-to-delete race is named); a skipped delete skips its dependent worktree row; merged branches ahead of `headRefOid` name each extra commit and where it landed.
