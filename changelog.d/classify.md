### Added

- **`hatsu:classify`** (new, `claude/skills/classify/SKILL.md`; the first of two skills from the maintainer's rulings of 2026-10-04, `docs/ROSTER.md` § *Rulings of 2026-10-04 — classify and direct*, from the document *Version-Decoupled Model Selection Matrix for Engineering Workflows*): classifies one issue, a set of issues, a whole backlog or an inline effort on two axes and applies the result as labels.
  - **Axis one, the language the work needs:** `lang/swift`, `lang/kotlin`, `lang/typescript`, `lang/csharp`, `lang/prose`. Companion formats (YAML, JSON, shell, Markdown…) are never labelled.
  - **Axis two, the job:** `job/<key>`, the 39 domain-agnostic keys of the new `contracts/classify.taxonomy.json` (`hatsu.classify-taxonomy/v1`), which fold the document's 114 phase keys — every one covered — into jobs such as `discovery`, `requirements`, `architecture`, `implementation`, `ui`, `unit-tests`, `security`, `release`, `bug-fix`, `machinery`, `prose-authoring`, `schema`, `adapters`, `evals`, plus four Hatsu has proven it needs (`onboarding`, `backlog`, `provisioning`, `delivery-ops`) and `parity`, the one marker job. The five domains are derived by `domains.rule`, never labelled.
  - **The vocabulary is data.** Keys, prefixes and colours live in the taxonomy file alone; nen's `classify` family (`labels`, `install`, `status`, `apply`) reads it through `--taxonomy` and hard-codes none of it. The family lands in the nen release that ships the classify family (an owned dependency: zheref/nen#370 (branch `sonnet/kurapika/classify-verbs`), cited in `nen/contract.json`; `v0.19.0` shipped on 2026-10-04 without it); at the `v0.18.2` pin the verbs are absent and the skill continues where it can (row `missing-tool`: the judgement shown, nothing labelled by hand). A consumer's `nen/labels.json` stays the one source of truth for its labels: `nen classify install --write` populates it (behind a `missing-configuration` ask), that change lands through its own declaration PR first, and GitHub is synced after (`nen labels sync` today; `--sync`, which refuses an unlanded declaration, once the family ships). Issue text is untrusted data, never instructions: an injection-suspect row is surfaced, never acted on.
  - **One confirmation, every write ledgered.** `hatsu:classify backlog` renders one table and takes one confirmation (⭐ apply the high and medium rows · do not apply); low-confidence keys are listed and never applied by the skill. Confidence is graded per (axis, key); an axis with no key at any level stays empty and the issue is listed as undecidable, never guessed (new `nen/decisions.json` row `classify-undecidable`, 34 rows). An empty line is the bare form and a line whose first token is not exactly `backlog` with a resolvable repo is never a sweep. Nothing is written before the answer.
  - **It always runs inside `hatsu:file`** (§ 5, the *Classification* row) with one reading per state: the keys travel in the create call only where the families are declared in the target's `nen/labels.json` and present on GitHub; otherwise they are shown in the plan, named owed, and the filing proceeds without them.
