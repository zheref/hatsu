### Changed

- **The private-name guard says `no ignore file` when none was read** ([#149](https://github.com/zheref/hatsu/issues/149)). `scripts/private_name_check.sh` used to report an absent default ignore file as `0 ignored by the maintainer's ignore file`, indistinguishable from a file that was read and ignored nothing; every ok line (`--allow-empty` included) and every refusal now say `no ignore file, so nothing ignored` when none was read, and a dangling default ignore-file link is a wiring fault (exit `2`) rather than a silent absence, and a host with neither `XDG_CONFIG_HOME` nor `HOME` set refuses at exit `2` naming why, where bash's unbound-variable exit `1` read as a finding. The other exit codes are unchanged, and the `redaction-guard` fixture proves each state (186 cases). `docs/PUBLIC-REDACTION.md` § *How it is guarded* records that the `redaction-tree` lane is red by design without the file and that a session hands that refusal to the maintainer, never judging it no leak; the 2026-10-13 #149 row in `docs/ROSTER.md` carries a dated pointer to the *#289 item 10* row that spent its 2(b) deferral.
