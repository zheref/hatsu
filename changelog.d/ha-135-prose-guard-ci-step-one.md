### Changed

- **Step one of the prose-diet guard in CI: `prose-size-check.yml` is registered in the workflow-policy validator and ships inert at `templates/`** ([#135](https://github.com/zheref/hatsu/issues/135)). The validator judges every pull request from the base, so the workflow's job, trigger, draft-skip guard, check creation and frozen guard step are learned one PR before the file moves under `.github/workflows/` (#80's order); a workflow pending in `PENDING_HOSTED_WORKFLOWS` is judged from `templates/` as if installed. The frozen guard step refuses to measure without a fresh fence token, and reads any exit but `0` and `1` as a wiring refusal. **The exact-head check each guard workflow creates and finishes is now frozen at both ends** in `plugin-bump-check.yml`, `surface-mirror-check.yml` and `prose-size-check.yml` alike, so its conclusion mapping cannot be edited into a green (QA-18). Every per-workflow table of the validator is checked at load to cover exactly its workflows, so a registration that misses one fails loudly. `scripts/prose_size_check.sh` resolves a symlink's whole chain before its root check, so a link to an in-root link that leaves the root is refused, with a fixture case. Plugin bumped to 0.107.0 (`templates/` and a shipped runtime script); mirrors restamped.
