### Added

- **The idle profile for batches, and the bounds an idle run needs (HR-5; D2, D3, D4, D5, D9).** `nen/workflow.json` gains `idle`: `decisions` (one resolution per `ask-once-per-run` row of `nen/decisions.json`, `default` where the row stars an option, `hold` otherwise; `harness-attribution-switch` and `host-nen-link` held because each stars an act on the maintainer's own harness or host, `cleanup-plan` held because an unattended remote branch deletion can close a stacked child, the five `spec-*` rows held (the starred `spec-capture-scope` and `spec-converge-filing` among them) because `dowsing-chain` is not an idle-run skill, `port-drift` held because its answer is a permanent canon record under the porting ruling, `publish-offer` refused because an idle run never reaches a release), `terminal` (`ready-at-prompt-or-integration`) and `budget` (`minutes`, the enforced bound; `tokens`, advisory and unread until zheref/nen#490 lands). `monitor` gains `localSlotFrees`, fixed at `merged` (HR-257, *Slots and stops*): the one key that frees a local slot at its merge, for every futon run, read by zheref/nen#498's `nen loop slots` (unreleased, not at the 0.24.0 pin; until the repin futon § 6 keeps the effort's `ready`/`prompted` flags false in its efforts file until the local merge); an `--idle` `start` fails on any other value. Each has a row in `contracts/config-catalogue.json` (domain `autonomy`, applied where the block is declared), written through `scripts/config_values.sh set`; `nen schema check` tolerates the block. `docs/WORKFLOW.md` gains the `idle` key table and § *Idle batches*.
- **A floor no file lifts, read from committed canon.** `start` reads the idle block from the committed `nen/workflow.json` of the remote default branch only (`origin/HEAD`, else `gh repo view`'s `defaultBranchRef`; SEC-15), never `HEAD` or a ref `HEAD`'s commit names, never the working tree; a default branch with no `nen/workflow.json` refuses `start` (exit 1, reason printed), and records that commit as `idle.source`. It fails at exit 1 when `publish-offer` is anything but `refuse`; when `host-nen-link`, `harness-attribution-switch` or `missing-maintainer-choice` is `default` (the 2026-09-23 ruling: that choice is never derived); or when any row whose options star nothing is `default`.
- **A typed `--idle` on `hatsu:futon` and `hatsu:kazaana`.** nen 0.24's `nen parse futon` reads the token as part of an exact label, so it is stripped before parsing. The run records every pre-answered row; a held or refused row, a G5, a *by hand* or *no verb* step, or the budget parks the effort as `parked:<row>` and the run moves on, with no picker shown. The run ends with every PR Ready at its merge prompt or merged into a non-main integration branch. It never merges into `main` and never reaches `getsuga` or `mugetsu`. futon § 12 and kazaana § 1 cite the WORKFLOW section.
- **The run manifest.** `scripts/futon_effort_record.mts` `start` writes contract `hatsu.futon.run/v0.2`. New `append` records `{issue, pr, base, kind, head}` for every PR the run opens, whatever its base, from the live PR. A re-append refreshes the PR's entry and never adds a second one. New `park` records a parked effort and `status` prints the manifest with elapsed minutes. On a v0.1 run `status` prints `manifest: absent`, omits `prs` and exits 2, and futon § 8 and kazaana § 5 treat that as the gate held. Both read the manifest instead of memory. A manifest lock older than ten minutes is a crashed writer's and is cleared. The `futon-effort-guard` fixture proves the manifest cases, the floor, the committed source, `overBudget`, a stale lock and `--idle` typed before `@`.
