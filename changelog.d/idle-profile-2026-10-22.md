### Added

- **The idle profile for batches, and the bounds an idle run needs (HR-5; D2, D3, D4, D5, D9).** `nen/workflow.json` gains `idle`: `decisions` (one resolution per `ask-once-per-run` row of `nen/decisions.json`, `default` where the row stars an option, `hold` otherwise; `harness-attribution-switch` and `host-nen-link` held because each stars an act on the maintainer's own harness or host, `publish-offer` refused because an idle run never reaches a release), `localSlotFrees` (`merged`, from ROSTER § *Rulings of 2026-09-30*, *Slots and stops*), `terminal` (`ready-at-prompt-or-integration`) and `budget` (`minutes`, `tokens`). Each has a row in `contracts/config-catalogue.json` (domain `autonomy`, applied where the block is declared), written through `scripts/config_values.sh set`; `nen schema check` tolerates the block. `docs/WORKFLOW.md` gains the `idle` key table and § *Idle batches*.
- **A typed `--idle` on `hatsu:futon` and `hatsu:kazaana`.** nen 0.24's `nen parse futon` reads the token as part of an exact label, so it is stripped before parsing. The run records every pre-answered row; a held or refused row, a G5, a *by hand* or *no verb* step, or the budget parks the effort as `parked:<row>` and the run moves on, with no picker shown. The run ends with every PR Ready at its merge prompt or merged into a non-main integration branch. It never merges into `main` and never reaches `getsuga` or `mugetsu`. futon § 12 and kazaana § 1 cite the WORKFLOW section.
- **The run manifest.** `scripts/futon_effort_record.mts` `start` writes contract `hatsu.futon.run/v0.2`. New `append` records `{issue, pr, base, kind, head}` for every PR the run opens, whatever its base, from the live PR. A re-append refreshes the PR's entry and never adds a second one. New `park` records a parked effort and `status` prints the manifest with elapsed minutes. futon § 8's `then` gate and kazaana § 5 read the manifest instead of memory. The `futon-effort-guard` fixture proves the manifest cases.
