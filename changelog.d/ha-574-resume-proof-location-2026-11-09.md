### Fixed

- **The `resume-proof` lane reads the run manifest's location from the first line of `nen run start`, not from its whole stdout.** `scripts/resume_proof.mts` located that manifest with `started.trim().split(' -- ').pop()`. `nen run start` prints the location on its first line and, when it actually wrote, a second line stating the permissions it used (`mode: file 0600, directory 0700`); `.trim()` does not touch the newline between them, so the parse returned `…/<id>.json\nmode: file 0600, directory 0700` and the row reported `ENOENT` against text it had assembled itself — as a *convergence divergence*, the one thing the lane exists to detect. The default branch has read 33/34 since the nen v0.30.0 repin, so every pull request against it carried a red `unit-tests` row that said an interrupted batch could no longer be resumed. It could: re-starting an existing run answers `existing`, re-parking an unchanged park answers `unchanged`, and the manifest's bytes do not move. A new `manifestLocation()` reads the first line only and, where that line carries no ` -- <path>`, throws a message quoting the line it could not parse, so a later change to what the dependency prints is a legible refusal rather than a missing file. Two proof rows assert both halves on printed text, because the mode line appears only on a write and a live run cannot be relied on to produce the case that broke the lane; the lane now reads 36/36. `scripts/resume_proof.mts` is not a plugin-shipped surface, so no version bump is owed.
