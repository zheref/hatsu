### Fixed

- **The `resume-proof` lane reads the run manifest from `nen run start --json`'s answer instead of scraping its prose (zheref/hatsu#574).** `scripts/resume_proof.mts` located that manifest with `started.trim().split(' -- ').pop()`. The verb prints the location on its first line and, when it actually wrote, a second line stating the permissions it used (`mode: file 0600, directory 0700`, added in nen v0.29.0 and reaching Hatsu at the v0.30.0 repin); `.trim()` does not touch the newline between them, so the parse returned `…/<id>.json\nmode: file 0600, directory 0700` and the row reported `ENOENT` against text it had assembled itself — as a *convergence divergence*, the one thing the lane exists to detect. The default branch has read 33/34 since that repin, so every pull request against it carried a red `unit-tests` row claiming an interrupted batch could no longer be resumed. It could: re-starting an existing run answers `existing`, re-parking an unchanged park answers `unchanged`, and the manifest's bytes do not move. The case now passes `--json` and reads the `outcome` and `path` fields, which is a contract rather than a shape, so the whole class of coupling goes with it — including the sibling `startsWith('existing')` / `startsWith('unchanged')` reads in the same block. An answer missing either field is refused by name, quoting one bounded excerpt with absolute paths elided, because a row's detail is transcribed into public prose. The row's divergence detail now names which of its three conditions failed instead of printing two outcomes that both read as correct. Two proof rows assert the contract read and the refusal on payloads, and were mutation-proved: removing the refusal takes the lane to 35/36 and exit 1. The lane reads 36/36. `scripts/resume_proof.mts` is not a plugin-shipped surface — checked against `plugin_bump_check.sh`'s own `path_is_plugin_surface`, not by eye — so no version bump is owed.
