### Changed

- **#355 Port rulings are `PT-{n}` from one global counter** ([#355](https://github.com/zheref/hatsu/issues/355)). The maintainer ruled on 2026-10-21, recorded in `docs/ROSTER.md` § *Rulings of 2026-10-21 — the port rule prefix (HA#355)*: the ports rule prefix is `PT`, and one counter runs across every pair file of the rulings directory. The answer is HR-34, re-confirming HR-9. `templates/ports/pair.md` carries `prefix: PT · numbering: global`. Citations keep the ruled form `<from>--<to> PT-<n> (branch <ref>, unmerged)`.
- `scripts/port_rule_reserve.sh` reads every `<rulingsDir>/*.md` (the `--pair-file`'s own directory) at the tip, at the run's HEAD and working tree, on every sibling `ports-*` branch, and in every open same-repository PR touching one. The next id is one past the highest anywhere. `--check` refuses one id in two pair files, including a tip row in a different file.
- **Exit 2:** a `--pair-file` with an empty, `.` or `..` segment, a leading `./` or a trailing `/`; a `--prefix` other than `PT`; a `--target` whose name is not a segment (`acme/.`, `acme/..`).
- **Exit 3:** any header line (`<!--` naming `prefix:` or `numbering:`, keys in any case, at any indent, in a file or in an open PR's added lines) that is not exactly one `prefix: PT · numbering: global`, with `global` followed by whitespace, `)`, `·` or `-->`; a headerless file is counted. A pair file named out of shape, its path printed. A first cell carrying another prefix (`SW-3`), or `PT-<digits>` that is not a row. Every GFM row form is counted: a pipe-less row, up to three leading spaces, `**`/`*`/backtick emphasis. A row in a fenced example is counted too, a safe over-count.
- **Exit 1, nothing reserved:** a failed git listing, blob or working-tree read.
- **Never read, or not others:** a fork PR is never read and is listed by number only. The run's own push and own PR are not "others" to `--check` when, and only when, they are ancestors of HEAD (the PR by its `headRefOid`); a same-named branch or PR of another run is counted. `--check` also flags one id in two rows of one pair file. A local head tracking `refs/pull/*`, or a remote whose URL is not origin's, is skipped and reported by count, never by name; a remote unset or `.` is read. `--json` escapes every control character.
- Every earlier refusal keeps its exit code, except the fork-PR reads, which are never made (exit 1 → 0). The `port-rule-guard` fixture proves each case (77 checks, at bash 5.3 and at `/bin/bash` 3.2).
- `hatsu:bankai-rule` §§ 2–3 state the rulings-path grammar and the prefix and header refusals. § 3 drops the G5 stop that held the global case. `hatsu:kamui` and `hatsu:bankai-handbooks` lose stale "not landed" and "ruled on its adoption PR" wording.
- The reservation stays linear in rows and costs no more than the one-file read it replaced: one listing per place, one blob batch and one judging pass for every place, whatever the number of pair files.
- The open-PR reads stay residue until zheref/nen#456.
- Plugin bumped to 0.130.0.
