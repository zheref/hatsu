### Added

- **`hatsu:senkaimon` — a consumer's open PRs tried one head at a time on a device** (zheref/hatsu#577). `hatsu:senkaimon <repo> [--target <name>]` shows the open-PR queue first, ordered by number, with every fork head and every head that changes `nen/contract.json` or `nen/workflow.json` listed ineligible with its reason; takes one authorization (new row `review-queue-authorize`) for the declared target and the core swap and launch; then per PR brings its pinned head into a review worktree, view-swaps it into core and launches it through `amaterasu` § 4, waiting for a running launch to release core and the target. Each tested head gets one unstarred merge-or-revise call (new row `review-verdict`) naming the PR, the tested head and the actual target: the merge path re-reads the head and `nen pr ready --require-head` before `en` § 5's prompt pinned to that head, never run; the revision path hands the typed feedback to a `ren` effort on the PR's branch. However the run ends, `nen wc swap --return` puts core back with its parked work restored. The name is the maintainer's pick (HR-384, record `R-2026-11-10-01`). Its read-only probes and the SC-1 proof protocol it still owes are `docs/ab/senkaimon.md`.
- **`scripts/gh_api_read.mts pr-head <owner/repo> <N>`** — one fixed GET projecting a PR's head SHA, head and base repositories, state and draft flag, so senkaimon can tell a fork head without raw `gh`; the `gh-api-read-guard` fixture pins the path and projection and refuses a hostile number or flag.
