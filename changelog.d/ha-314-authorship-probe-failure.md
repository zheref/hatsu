### Fixed

- **The provenance guard no longer calls a failed merge proof an old Git, and no longer needs the object store writable** ([#314](https://github.com/zheref/hatsu/issues/314)). `scripts/branch_authorship_check.sh --trunk` used to self-merge the trunk with `git merge-tree --write-tree` before judging anything and report every nonzero exit as `--trunk needs git >= 2.38`, so a supported Git whose object store the sandbox would not let it write was sent toward a Git upgrade. The capability is now read off `git merge-tree -h`, which writes nothing; the merge proof runs only for a trailer-less merge whose exemption must be proved, and it writes its tree into a throwaway object directory under `${TMPDIR:-/tmp}` (named by a template, so macOS honours `TMPDIR`; the repository's objects as its alternate; removed on exit), so it adds no object to the repository's store — Git may refresh the mtime of an object the store already holds, and where that is refused the tree is written to the throwaway directory — and a read-only store proves the same merge. Every Git read runs with `GIT_NO_REPLACE_OBJECTS=1` and a `GIT_GRAFT_FILE` that cannot exist, so a `refs/replace` entry cannot pass an evil merge off as the clean one and `info/grafts` cannot hide a commit from the range: the guard judges the objects a push sends. The proof runs with `GIT_NO_LAZY_FETCH=1`, so a partial clone missing a blob it needs fails closed rather than fetching on the caller's credentials (Git 2.44 or later; an older Git ignores the variable and may still fetch). A proof Git still cannot complete — any exit but `0` clean or `1` conflicted (unrelated histories, a shallow clone, a partial clone that would need a fetch, a signal), or exit `0` with no tree id — is exit `2` naming the commit and Git's exit, quoting at most three lines and 300 characters of Git's sanitised stderr as `git said (untrusted):`, read apart from the stdout the tree id comes from; it points at the harness's approval path only when the quoted lines themselves report a permission refusal, naming the directory actually used, and never at replacing Git. Findings are held until the range is through, so that exit `2` prints none. The `publish-integrity-guard` fixture now holds 138 cases (88 on `main`; #314 adds 50): 25 of the 50 fail against `main`'s guard and the other 25 pin verdicts it already gave. Plugin bumped to 0.119.0 and the three surface mirrors restamped.
