### Fixed

- **The provenance guard no longer calls a denied object-store write an old Git** ([#314](https://github.com/zheref/hatsu/issues/314)). `scripts/branch_authorship_check.sh --trunk` used to self-merge the trunk with `git merge-tree --write-tree` before judging anything and report every nonzero exit as `--trunk needs git >= 2.38`, so a supported Git whose object store the sandbox would not let it write was sent toward a Git upgrade. The capability is now read off `git merge-tree -h`, which writes nothing; the merge proof runs only for a trailer-less merge whose exemption must be proved, and a proof Git could not run (any exit but `0` clean or `1` conflicted) is exit `2` naming the commit, Git's exit status and its sanitised error, pointing at the harness's normal approval path and never at replacing Git. Findings are held until the range is through, so that exit `2` prints none. The `publish-integrity-guard` fixture proves unsupported, write-denied and successful proofs apart (98 cases; the new ten fail against the old guard). Plugin bumped to 0.117.0 and the three surface mirrors restamped.
