### Fixed

- **The provenance guard no longer calls a failed merge proof an old Git, and no longer needs the object store writable** ([#314](https://github.com/zheref/hatsu/issues/314)). `scripts/branch_authorship_check.sh --trunk` used to self-merge the trunk with `git merge-tree --write-tree` before judging anything and report every nonzero exit as `--trunk needs git >= 2.38`, so a supported Git whose object store the sandbox would not let it write was sent toward a Git upgrade. The capability is now read off `git merge-tree -h`, which writes nothing; the merge proof runs only for a trailer-less merge whose exemption must be proved, and it writes its tree into a throwaway object directory (the repository's objects as its alternate, removed on exit), so the repository's store is never written and a read-only one proves the same merge. A proof Git still cannot complete — any exit but `0` clean or `1` conflicted (unrelated histories, a shallow or partial clone, a signal), or exit `0` with no tree id — is exit `2` naming the commit and Git's exit, quoting at most three lines and 300 characters of Git's sanitised stderr as `git said (untrusted):`, read apart from the stdout the tree id comes from; it points at the harness's approval path only when Git's own text reports a permission refusal, and never at replacing Git. Findings are held until the range is through, so that exit `2` prints none. The `publish-integrity-guard` fixture now holds 122 cases (88 on `main`; #314 adds 34): 14 of the 34 fail against `main`'s guard and the other 20 pin verdicts it already gave. Plugin bumped to 0.118.0 and the three surface mirrors restamped.
