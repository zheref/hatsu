### Fixed

- **The consumer trailer check recognises its own check run again, and never leaves it in progress (zheref/hatsu#562).** GitHub replaces the `details_url` of a check created with the Actions token by its own `https://github.com/<owner>/<repo>/runs/<check id>` page, so `scripts/consumer_trailer_ci.mts` `identity()` rejected every check it had just created, failed the `trailer-policy-runner` job and left the check `in_progress` — blocking consumer pull requests at CON-32(a) on machinery rather than content. Identity now rests on the fields GitHub preserves — check ID, name, head SHA, `github-actions` producer and the external ID that already binds workflow ref, run id and attempt — and a response differing in any of them is still refused. The created check's ID is bound before the response is verified, so a refusal after creation completes the check with `failure` instead of leaving it open. The `consumer-trailer-guard` fixture's `gh` stub now rewrites `details_url` as GitHub does, with a regression test for the rewrite and one per refused identity proving the check is completed with `failure`. Consumers pick the fix up through tenkai's re-render of the script at their base. Plugin 0.162.1, mirrors regenerated.
