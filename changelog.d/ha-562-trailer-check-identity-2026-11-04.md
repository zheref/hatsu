### Fixed

- **The consumer trailer check recognises its own check run again, and completes it on failure (zheref/hatsu#562).** GitHub replaces the `details_url` of a check created with the Actions token by its own `https://github.com/<owner>/<repo>/runs/<check id>` page, so `scripts/consumer_trailer_ci.mts` `identity()` rejected every check it had just created, failed the `trailer-policy-runner` job and left the check `in_progress` — blocking consumer pull requests at CON-32(a) on machinery rather than content. Identity accepts that rewrite beside the requested run URL (as 0.162.1 does) and still compares check ID, name, head SHA, `github-actions` producer and the external ID that already binds workflow ref, run id and attempt; a response differing in any of them, or carrying any other `details_url`, is still refused. The created check's ID is bound before the response is verified, so a refusal after creation completes the check with `failure` instead of leaving it open, whenever GitHub returned a usable ID; a lost POST response still leaves its check in progress, since the publisher never looks a check up. A failed check's summary now links the workflow run and its text lists the offending short SHAs, so the check itself names the commit. The `consumer-trailer-guard` fixture's `gh` stub now rewrites `details_url` as GitHub does, with a regression test for the rewrite, one each for a refused name, producer, head and external identity proving the check is completed with `failure`, and six for a POST response without a usable ID proving no PATCH is sent. Consumers pick the fix up through tenkai's re-render of the script at their base. Plugin 0.162.2, mirrors regenerated.
