### Fixed

- **`cleanup` admits a worktree path as a path, never as a Git branch name** ([#333](https://github.com/zheref/hatsu/issues/333)). § 4 put every name taken from the repository, worktree paths included, through `git check-ref-format --branch`, which refuses every native absolute path, so a clean merged worktree under `.nen/worktrees/` was always a named row and § 5's `git worktree remove -- <wt>` was unreachable. Branches and remote heads keep the ref rule; a worktree path is now admitted by the new `scripts/cleanup_path_admit.sh`, whose header is the rule: a canonical main-worktree core, an absolute path in `^/[A-Za-z0-9._/-]+$` with no `.`/`..`/empty component or trailing slash (traversal refused as spelled), strictly under `<core>/.nen/worktrees/`, no symlink on the way, listed exactly in `git worktree list --porcelain` and not on the trunk. A refused path stays a named row with no command; an admitted one is classed by § 5's worktree rows (merged and on-branch-clean deterministic; closed, no PR, dirty or detached proposed; locked or open named) and carries the one literal `git -C '<core>' worktree remove -- '<path>'`, printed and never run before the maintainer's pick, never `--force`. Its `--self-test` runs as the new `cleanup-path-guard` lane; Shizuku's name rule cites it; the invocation evidence moved to `docs/ab/cleanup.md` with the admission record. Plugin bumped to 0.119.0 and the three surface mirrors restamped.
