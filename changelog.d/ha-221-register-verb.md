### Changed

- **The Rikugan register's data document is the verb's** ([#221](https://github.com/zheref/hatsu/issues/221), zheref/nen#276): `backlog-board` § 3 and `rikugan` §§ 3–4 call `nen report data … --register <desk>` and pipe its document into `nen report render --variant register|final`; the hand-built register builder is retired. The desk a run composes is the judgement half only (variant, title, scope, gate, the asks per gate with their lettered options and one `star`, optional row marks), every fact — notation, verdict, labels, checks, threads, links, head, the five tallies and the spend from the ledgers — is nen's, and a desk that carries a `verdict`, or any key nen does not read, is refused; rikugan reads the facts in a plain pass first and composes the desk from them. Canon now writes down the five tally definitions nen 0.21.0 implements: `tallyScope` (the objects in scope), `tallyNeedsYou` (the asks across every gate), `tallyBlockers` (open PRs with a red check, an unresolved thread or a `DIRTY` merge state), `tallyReady` (open PRs whose verdict is `ready` and that are not blockers), `tallyInFlight` (the remaining open PRs). `black-voice` § 6's per-criterion rows are not objects `--register` reads, so that caller keeps the hand-built document until nen carries criterion rows (a nen follow-up). The end-to-end futon run rendered this way — the run that lands this stack — is owed to `docs/ab/futon.md` on this branch before its PR opens.
