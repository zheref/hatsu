### Fixed

- **A placed copy is Hatsu's own only where its marker is generated** (zheref/hatsu#531, `SEC-7`; Feitan's F5 on the pull request closing zheref/hatsu#530). The predicates that authorise the warm-up's unattended full-surface install, and decide which placed files a refresh may replace or remove, asked whether a marker's text appeared anywhere in a file's bytes, so a page that only quoted a concrete marker passed. They now share one reader, `scripts/surface_marker.sh` (POSIX sh and awk, sourced by `scripts/surface_bootstrap.sh`, `scripts/permissions_pack.sh` and `hooks/session-start.sh` with its three mirrors), which reads the one line nen writes the marker on: the first markdown line after any frontmatter, a hook script's line 2, a JSON file's line 2. It accepts the generated form alone, in the current and the pre-#530 stamped grammar, plus the retired Antigravity generator's marker where that generator wrote it. The surface name is compared with `=`, never matched, so `codex-experimental` is not `codex`. The retired Antigravity marker no longer counts as a hook script's ownership on codex or cursor. A verified plugin root without the reader refreshes nothing and names the file. The reader is one awk run per file, with no subshell of the caller and silent under a caller's `set -x`: per-file trace records from it broke the Bashcov capture of `surface-bootstrap-guard` on every run until they were removed. Before and after over the 258 generated files under `surfaces/`, every file keeps its verdict under every reader. A name carrying a newline no longer splits the session-start hook's file list into a path outside the surface directory (Feitan, F1). The bootstrap's ownership check reads one kind per destination: its rows were one ungrouped `&&`/`||` chain, so a hook script also ran the skill reader, and an antigravity `--install-all` treated an `.agents/hooks/` script another surface's marker names as replaceable, failing mid-transaction; that script is now kept and named. The reader is frozen to fixes only, BC-11 debt pending a nen verb that reads one file's generated marker (zheref/nen#658) and Hatsu's repin to it, by the maintainer's ruling [HR-392](docs/ROSTER.md#hr-392); ROSTER 1.82.0.

### Added

- **A mirrored source carrying a concrete marker literal is refused before it is checked or generated** (zheref/hatsu#531, AC-3). `scripts/surface_mirror_check.sh` and `scripts/surface_mirror_regenerate.sh` refuse by file and line, at exit 1, a skill, persona or include, `hooks/hooks.json` or a hook script, `claude/rules/hatsu.md`, `contracts/permissions.json` or `.claude-plugin/plugin.json` that carries `GENERATED by nen surface mirror (surface: <name>` with a concrete name, or the retired Antigravity marker. An older session-start hook still placed in a consumer's workspace matches the text anywhere in a file. Prose writes a placeholder, `(surface: <s>)`. The scan reads every source nen mirrors: dot-named skill and persona pages, and every file beside `hooks/hooks.json` whatever its extension (Feitan, F2). A source it cannot read is refused at exit 2, named, rather than read as clean.
