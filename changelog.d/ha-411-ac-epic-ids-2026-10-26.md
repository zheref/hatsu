### Added

- **The issue section catalogue reads Akatsuki's criterion rows beside Hatsu's (zheref/hatsu#411, HR-11).** `contracts/issue-sections.json`'s acceptance row admits `- AC-{n}: …` and Akatsuki's `- AC-{epic}-{nnn} (P{n}): …`, the id group (`[0-9]+(?:-[0-9]{3})?`) taken whole as the criterion; it declares the resolved form `- ~~AC-{id}~~ withdrawn: <reason> (<YYYY-MM-DD>)` as `resolvedPattern`, the field the question row already uses, so a withdrawn criterion is never live; and a `requirements` section (`## Requirements`, Akatsuki's epic and child heading, required by no kind) is read for criteria. At nen 0.28 `nen issue criteria` reads the Requirements heading and `nen issue body-check` admits a withdrawn `AC-{n}` row in order; `requirements` is optional on the `epic` kind so body-check shape-checks its rows, the two headings are alternatives, never both, and the pattern is deliberately looser than either shape (one id group serves both). Both Akatsuki forms still read as unrecognised in `nen issue criteria` and `nen pr converge` until nen takes the id from this pattern (zheref/nen#519, NN-PR-#548; the tail is inside that head's safe subset) and reads the annotation and skips the resolved row (zheref/nen#553, filed by this build); until then body-check also misreads an `AC-{epic}-{nnn}` row's id as `AC-{epic}`, and a body carrying both headings passes, both pinned in the fixtures. The criteria lane's fixture holds the grammar directly and pins the nen misses; `templates/pr-body/verify.md`, `docs/PR-SECTIONS.md` and `docs/config/plugin-registries.md` say that `<k>` in `<CODE>#<N>/AC-<k>` is the id exactly as the issue writes it.
