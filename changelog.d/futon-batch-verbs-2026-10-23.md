### Changed

- **futon runs on nen's run manifest (zheref/hatsu#423).** `scripts/futon_effort_record.mts start` opens the manifest through `nen run start --id <run id> --target --repo [--idle-answers]` and only then writes its ownership record, contract `hatsu.futon.run/v0.3` (id, repo, invocation, selector, `startedAt`, `dry`, and the idle profile's `terminal`, `budget`, `source`; no PRs, no parks, no answers). Every opened PR is `nen run append`, every park `nen run park`, the `then` gate and the register `nen run verify`, the budget `nen run budget --max-minutes --max-tokens` with the committed profile's values, and futon § 6's slots `nen loop slots --from-run <run id> --target` — no typed efforts file. The record's `append`, `park` and `status` are retired and refuse by name; a new `profile` prints the ownership record. A run started before this release has no nen manifest, so its `then` gate is held. Park rows are `[a-z0-9-]+`: `g5-<class>` and `residue-<skill>` replace the colon forms nen refuses.
- **`--idle` is nen's to read.** `nen parse futon` reads the token (nen `0.26.0`); the record no longer strips it, and still refuses a doubled `--idle`, a modifier after `then` and any unknown `--` token before it, which nen would fold into the label.
- **The issue shape is nen's (HR-4).** `hatsu:build` § 2, `hatsu:futon` § 2, `hatsu:file` § 4 and `hatsu:emperor-time` § 6 run `nen issue questions` and `nen issue body-check --requirements-from "$hatsu_root/contracts/issue-sections.json"`, stated once in `docs/config/plugin-registries.md` § *The check*. `scripts/issue_body_check.mts` and its fixture are retired; the `issue-shape` lane now runs `scripts/issue_sections_fixture.mts`, which holds the templates to the catalogue and runs the verified nen over them. A vague adjective or technology term on an acceptance row is now an advisory, never a miss.

### Added

- **`hatsu:futon <repo>@<selector> --idle --dry-run` (zheref/hatsu#424).** The idle profile's rehearsal in one typed line: every read-only verb runs, nothing is authored, every effort's dry end state is parked by its row (`dry-prompt` inside the local cap, `dry-waiting-slot` past it, or the stop the read predicts), and the record says `dry: true`. The record lifts `--dry-run` off before nen's parse until nen reads it; without `--idle` it is refused. `docs/ab/futon.md` § 2026-10-23 is the proof: 25 issues, 7 authorable in one night. This release is `0.140.0`.
