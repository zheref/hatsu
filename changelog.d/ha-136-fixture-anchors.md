### Changed

- **A comment can no longer disarm a hostile fixture in `scripts/workflow_runner_policy_check.rb`** ([#136](https://github.com/zheref/hatsu/issues/136)). The self-test built its fixtures with `String#sub`, which edits the first occurrence of a literal, so on #134 a comment spelling the trusted contract path took the edit meant for `surface-mirror-check.yml`'s pin read, and a trailing comment could take it while the suite stayed green. Every edit of a real workflow now goes through `fixture_sub`: it tries each occurrence and keeps the first that changes what the parser and the shell see (YAML comments are not in the parse; `fixture_code` drops a run's comment text, trailing comments included), inside the one step the fixture names or outside every step when it names none. A fixture no occurrence satisfies, or one whose scratch tree is refused before its edit, stops the self-test as a **BROKEN FIXTURE** naming the case. The hand-built fixture tables check through `fixture_changed!`. Every existing case is still refused for the same reason, and `surface-mirror-check.yml` no longer warns authors against spelling the path. No shipped surface changes.
