### Fixed

- **The macOS in-session bell plays its sound and can no longer hang (zheref/hatsu#516).** `scripts/bell_notify.sh` passed `afplay -- <file>`, an option the player rejects, so the sound rung never played and the error was reported as a missing seat; the sound is an absolute allowlisted `/System/Library/Sounds` path, so the player now takes it bare. The OS notification waited synchronously with no deadline, and a hung `osascript` blocked the turn for more than five minutes and the sound rung behind it. Each rung now runs as the script's own background child under a documented finite deadline, `--deadline <seconds>` (1 to 60, default 5), with no GNU `timeout`: past it the child gets TERM, then KILL a second later, by its PID only, never by name or pattern, and is reaped before the sound rung runs once. The result lines now tell an absent tool (`not applicable`) from one that ran and reported an error (`failed (exit <n>: <stderr>)`) and one that never returned (`timed out after <n>s, its own child stopped`), and none of them reads `sent` or `played`; `sent` still never confirms delivery. The `bell-guard` fixture adds deterministic success, unavailable, failure, hung-child and TERM-ignoring cases, a same-named decoy that must survive, and the bound measured. `docs/surfaces/README.md` § *Shared rules* says the same. The Stop hook had the same hang: `hooks/stop-bell.sh` waited on `osascript` with no deadline. On macOS and Linux each of its rung tools now runs as the hook's own child under `HATSU_BELL_DEADLINE` (whole seconds, 1 to 5, default 5; any other value reads 5). A watchdog, also the hook's own child, TERMs and then KILLs that one PID, only while `ps` still names the hook as its parent. A rung that timed out is not tried again for a later marker in the same run, so the sound still plays once after a hung notification, and no rung starts past a 12-second budget, so the run stays inside the hook's 15-second timeout and every marker is still cleared; an EXIT trap stops this run's own watchdog and child and removes its row file. Windows is unchanged and still untested. `scripts/stop_bell_fixture.mts` proves hung and TERM-ignoring rungs bounded per rung and across three markers, with a decoy named `osascript` untouched, and drops its sound expectations, named, on a host without the macOS system sounds. The fallback's liveness poll is paced by `kill -0`, but every signal first checks bash's job table, so a reaped and recycled PID is never signalled. Out of scope, and filed as zheref/hatsu#556: whether BC-11 moves this timeout logic to TypeScript, and naming `HATSU_BELL_DEADLINE` in `docs/WORKFLOW.md` § 6. Out of scope here: the Notification Center/XPC seat error itself. Plugin 0.160.0 (a minor: a new option and a new switch), mirrors regenerated.
