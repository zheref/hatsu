### Fixed

- **The consumer trailer check accepts the `details_url` GitHub rewrites on its check run.** `scripts/consumer_trailer_ci.mts`, the trusted publisher hatsu:tenkai renders into every consumer's base branch, required the check-run response to echo the `details_url` it requested, `https://github.com/<repo>/actions/runs/<run id>/attempts/<attempt>`. GitHub never persists that value for a check run a GitHub Actions token creates: the response carries the check's own page, `https://github.com/<repo>/runs/<check id>`, while `name`, `head_sha`, `app.slug` and `external_id` come back exactly as sent. So the job failed on every head with "GitHub check response does not identify this producer, workflow run and exact PR head" and the `forbidden-commit-trailers` check stayed `in_progress` forever (observed live on a consumer, 2026-11-04). `identity()` now accepts the requested run URL or exactly that rewrite, on the create and the completion responses alike; the id, name, head, producer and `external_id` comparisons are unchanged, so the producer, workflow run and attempt stay bound. The `consumer-trailer-guard` fixture proves the rewritten form is accepted, that the publisher still requests the run URL, and that six other URLs (another check id, another repository, another attempt, another run, plain http, a trailing slash) are still refused. Consumers carrying the old rendered copy read `drifted` and are repaired by a Tenkai re-render. Plugin 0.162.1, mirrors regenerated.
