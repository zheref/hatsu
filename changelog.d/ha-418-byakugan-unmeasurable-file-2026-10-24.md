### Added

- **`hatsu:byakugan` § 8 has an option for a touched file no declared lane measures (zheref/hatsu#418).** Option **E** applies where no lane or target in the declaration measures this file's target, on any host. It names the missing capability with the line that shows it absent, reports the file as `not measurable here — <capability>` in the percent column rather than a number, has the PR state it, and leads to a proposal at the declaration gate (G4 in a canon repository, G2 in a consumer one) for a lane or target that can measure the file, or a seat on such a lane. It never leads to a lowered ladder or an added exclusion. ⭐ goes to E wherever it holds, and A now means tests that are writable and runnable on a lane that measures the file. § 8 keeps one cause per option, so snapshot-tested UI, generated code and a lane-bound target are no longer folded into one waiver, and the picker renders at most four options: B always, plus whichever of A, C, D and E apply, with each file's option named in the chat table. § 9 tells apart (a) a lane that seats coverage, (b) a lane that declares coverage while no declared lane measures this file, which reaches § 8's stop, and (c) a host that lacks a capability the declaration expects, reported `unread — <host, capability>`, whose remedy is host repair rather than a declaration proposal. § 5 rule 2 now excludes only file kinds or languages the tool never measures, and § 2's band table carries the three labels, which take precedence over every band. No change to `coverage.minimum`, the bands or any nen verb.
