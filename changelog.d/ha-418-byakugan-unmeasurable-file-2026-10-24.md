### Added

- **`hatsu:byakugan` § 8 has an option for a touched file no declared lane measures (zheref/hatsu#418).** Option **E** applies where no lane or target in the declaration measures this file's target, on any host. It names the missing capability with the line that shows it absent, reports the file as `not measurable here — <capability>` in the percent column rather than a number, has the PR state it, and leads to a proposal at the declaration gate (G4 in a canon repository, G2 in a consumer one) for a lane or target that can measure the file, or a seat on such a lane. It never leads to a lowered ladder or an added exclusion. ⭐ goes to E wherever it holds, and A now means tests that are writable and runnable on a lane that measures the file. § 8 keeps one cause per option, so snapshot-tested UI, generated code and a lane-bound target are no longer folded into one waiver, and the stop groups its files by applicable option set and asks one picker per group: B plus that group's options, two to four and never padded, exactly one ⭐ by the order E, A, C, D (B never), with the line that would tip it stated. Each file's group is named in the chat table, an answer binds only its group's files, and an unbound file returns to § 8 as a fresh stop. A file shown to be § 9 (b) leaves the § 6 test loop at once for option E. § 9 tells apart (a) a lane that seats coverage, (b) a lane that declares coverage while no declared lane or target measures this file on any host, with (a) taking precedence for its own lane, which reaches § 8's stop, and (c) a host that lacks a capability the declaration expects, reported `unread — <host, capability>`, whose remedy is host repair rather than a declaration proposal. § 5 rule 2 now excludes only file kinds or languages the tool never measures, and § 2's band table carries the three labels, which take precedence over every band. No change to `coverage.minimum`, the bands or any nen verb.
